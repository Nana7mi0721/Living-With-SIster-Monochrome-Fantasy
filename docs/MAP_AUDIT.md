## 2. 页面激活规则：「最高活动页」

### 2.1 算法（`crates/wolf-format/src/mps.rs` 的 `MapEvent::active_page_index`）**已验证**

```
active_page(ev, get_var):
    for page in reverse(ev.pages):           # 从最后一页往前扫
        if page.conditions_met(get_var):     # 4 个槽全部成立（未启用的槽恒成立）
            return page                      # 第一条命中即胜出
    return None                              # 所有页都不成立 => 事件不出现
```

两条必须记住的推论：**(1)** 页码大 = 优先级高，所以「例外 / 覆盖」页写在后面；
**(2)** 没有启用槽的页（`raw_sw == [0x20,0x20,0x20,0x20]` 之类）恒成立，是「无条件兜底页」，
放在最后就永远赢、放在前面只在更高页都不成立时赢。

### 2.2 条件槽编码 **已验证**

每页 4 个槽，槽 `i` 的原始字节 `trigger_switches[i]`：

| 位 | 含义 |
| :--- | :--- |
| 低 4 位 | `1` = 该槽启用；`0` = 停用（**停用槽里的变量号与阈值是陈旧残留，不可使用**） |
| 高 4 位 | 运算符：`0 >` / `1 >=` / `2 ==` / `3 <=` / `4 <` / `5 !=` / `6 按位与 |
| 配套数组 | `trigger_variables[4]`（u32 魔法变量号）、`trigger_values[4]`（s32 阈值） |

变量号沿用魔法寻址：`1000000+n` = Ev Self 自变量 n，`2000000+n` = 通常变量 n，`9000000+n` = 系统变量。
本库的自变量高段（`1100006` / `1100009` = self100006 / self100009）由引擎写入，语义见 §9 未验证项。

实测分布（C5）：

| 范围 | 条件槽数 | 启用槽 | 原始字节直方图 | 启用槽运算符 |
| :--- | --: | --: | :--- | :--- |
| 注册 6 张（115 页） | 460 | 201 | 启用 `0x11×25 0x21×167 0x31×2 0x51×7`；停用 `0x10×2 0x20×255 0x50×2` | `>=×25 ==×167 <=×2 !=×7` |
| 全部 9 张（134 页） | 536 | 208 | 启用 `0x11×25 0x21×173 0x31×3 0x51×7`；停用 `0x10×2 0x20×324 0x50×2` | `>=×25 ==×173 <=×3 !=×7` |

**只有 4 种运算符真的被用到**：`==`（压倒性）、`>=`、`<=`、`!=`；没有 `>`、没有 `<`、没有按位与。
停用槽的低 4 位恒为 0，高 4 位只见过 1 / 2 / 5（编辑器残留的上一次运算符）。注册 6 张的 201 个启用槽共引用
**56 个不同变量**（54 个通常变量 + `self0` + `self100006` + `self100009`）。

页尾字节：全部 9 张 134 页里 `0x7A` 有 132 页、`0x00` 有 2 页（`Map024.mps` offset 234、
`Dungeon.mps` offset 17716，见 `docs/FORMAT_SPEC.md` §5.6.1 的容错约定）——注册 6 张里只有 Map024 那 1 页是 0。

### 2.3 实例：global 62 决定出现哪一页 **已验证**

`SampleMapA.mps` 事件 9 `■深夜UI表示1`（0,35）有 10 页，全部 `parallel`，第 i 页的条件是 `v62 == i+1`：

| v62 | 0 | 1 | 5 | 10 | 11 | 16 | 99 |

| 事件 9 活动页 | 无（不出现） | p0 | p4 | p9 | 无 | 无 | 无 |

### 2.4 优先级分析：没有一页是「永远赢不了」的 **已验证**

对每个多页事件穷举「能让任一条件改变真值」的赋值组合（§4.1 的断点域），统计每页在多少组合里胜出：

即没有任何一页在枚举域里不可达。逐事件的胜出计数见 §8 每张图后面的优先级小节。

## 4. 死页审计：0 个死页

### 4.1 方法：断点枚举 **已验证**

对每个多页事件：

1. 收集该事件所有**启用**条件槽引用的变量集合 V。
2. 对每个变量 v，取候选值 `{0} ∪ {t-1, t, t+1, t^1, t|1}`（t 是 v 在某个槽里的阈值）—— 这是「能让某个
   `==` / `>=` / `<=` / `!=` 条件改变真值」的最小充分集。
3. 取笛卡尔积，对每个赋值按 §2.1 的倒序扫描算出胜出页。
4. 一页「活」当且仅当它在至少一个赋值里胜出；「死页」= 从未胜出。

例：`SampleMapA.mps` 事件 4 的 5 页引用 `v68 v69 v62 v298 v67 v302 v464 v57 v63 v60` 十个变量，
候选值合计 **331 776** 个组合（C9 实测），全跑完只需数秒。

### 4.2 结果 **已验证**

- **25 个多页事件、134 页里没有任何死页**：每一页都能在某个赋值下胜出。
- 也没有「被无条件兜底页彻底遮蔽」的页：恒成立的页（无启用槽）都出现在单页事件里；
  多页事件里不存在「高页无条件」的情况 —— 作者把兜底页都放在**最低**优先级（页码最小）。

### 4.3 局限（必须写清楚，别过度声称）

这是**静态可满足性**：证明「存在一组变量值让该页胜出」，不证明「运行期真的会走到那组值」。以下两点本审计**没有**覆盖：

- 变量是否真的被写：`self100006` / `self100009` 等自变量由引擎在特定时机写入，写入时机未验证（§9）；
  若引擎从不写某个变量，则该页实际不可达。
- 触发方式是否可达：`confirm` 页要求玩家真的点到**事件所在格**；本作事件格与图片矩形是两套坐标（§5），
  「点不到」属于运行期问题，不属于格式问题。

## 5. 没有可走的地图图形：这是点触（point-and-click）游戏 **已验证**

### 5.1 证据一：注册 6 张的 115 页 `graphic` 全是空串

注册 6 张共 115 页，每页的 `graphic` 都是 `""`、`graphic_chip_id` 都是 `0xFFFFFFFF`（4294967295）：
每张图的「不同页图形」计数都恰好是 1（只有空图形），行走图通道在这些地图上完全没被使用。

对照组（三张孤立地图）恰好相反，说明这个字段的解码本身没问题：`SampleMapB.mps` 6 页里有 4 页带行走图
（5 种，如 `CharaChip/[Chara]Hero3_USM.png`）、`Dungeon.mps` 6 页里 2 页、`Map002.mps` 7 页里 2 页
（`CharaChip/Bomb.png`）。**注册地图一张都没用行走图**——「地图只是背景板」这个结论只对注册地图成立，且对它们全部成立。

### 5.2 证据二：交互全部走图片 150 + 悬停 124

| 项目 | 注册 6 张 | 控制组 `SampleMapB.mps` |
| :--- | --: | --: |
| `150 Picture`（画/动/删图片） | **3 648** | 0 |
| 　其中字面图片号 | 3 502（235 个不同号，3..100000） | 0 |
| 　其中变量间接给号 | 146 | 0 |
| `124 SetVariableEx` 总数 | 464（sub `0x3000`×104 + `0x4000`×360） | 0 |
| 　其中 `sub=0x4000 field=8` = **光标悬停** | **358**（SampleMapA 255 / SampleMapA_1 103） | 0 |
| `123 InputKey`（键盘） | 172（TitleMap 2 / SampleMapA 62 / SampleMapA_1 108） | 0 |
| `201 Move`（角色移动） | 6 | 0 |

358 条悬停读取分布在 `SampleMapA` 的 15 个事件与 `SampleMapA_1` 的 6 个事件里（C8），操作
**198 个不同图片号**，结果只写进两个自变量槽 `self100000`（`1100000`）与 `self100003`（`1100003`），
紧接着几乎总是 `111 VariableCondition`「没悬停就跳过」。这就是本作的全部交互模型：

> **地图图层只是背景；按钮是「图片」；判定是「光标是否落在图片矩形内」；状态机是通常变量。**

`docs/OPCODE_124.md` §5.3 已把 field 8 的判定规则写全（1 = 悬停、0 = 未悬停、-1 = 图片不存在），移植时照抄即可。

### 5.3 控制组的意义

`SampleMapB.mps`（WOLF 示例村）：`150 == 0`、`124 == 0`、6 个事件全是 confirm/touch —— 它才是
「有走图 + 走到事件格触发」的传统 RPG 写法。本作六张注册地图**一张都不是这种**，所以任何以
「玩家走到事件格」为前提的移植假设都会落空。
