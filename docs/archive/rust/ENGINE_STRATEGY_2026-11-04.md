# 是否转向 Godot 的评估（2026-11-04）

> **历史归档（2026-11-14）**：本文“暂不迁移”的结论已被 Godot 重制决策覆盖。
> 当前决策见 [`../../godot/DECISIONS.md`](../../godot/DECISIONS.md)；不要按本文继续评估或推荐 Rust/GDExtension。

> 背景：用户在看到一批 UI/交互问题后提问：“在有这么多画面 bug 的情况下，是不是应该转向用 Godot 来开发了？”
> 本文是决策备忘，不是路线图变更；当前路线仍是 Rust 重写。

## 结论

**暂不建议整体迁移到 Godot，也不建议现在重写。**
先把当前 Rust 版本当作“引擎内核”保留，优先修 P0/P1 的输入、状态和 UI 层问题。
如果后续证明渲染/UI 层无法用现有 Rust 架构维护，再考虑 **Rust 内核 + Godot 表现层（GDExtension/FFI）** 的混合方案，而不是把整个项目推倒重来。

## 为什么不是“直接换 Godot”

### 1. 已完成的是最难复用的部分

当前工程已经完成：

- 8 种二进制格式的解析（Game.dat / CommonEvent / .mps / 三个数据库 / TileSetData / .wolf / .sav）
- 50 种 opcode 的 VM/事件解释器
- 存档层：官方 .sav 往返、8/8 零售存档逐字节一致
- 地图/角色层、战斗、H 场景、音频、时间日程、标题/消息/选择
- 数百个测试、视觉基线、打包与启动性能优化
- `release/` 可双击运行，4067 files 打包校验通过

这些和“用哪个 UI 框架”几乎无关。换 Godot 后，格式解析、VM、存档兼容、事件调度仍然要重写；UI 变简单了，但工作量不会消失。

### 2. 当前 bug 大头不是“渲染技术不够”

用户本轮报的 13 类问题，初步分类：

- 输入路由/状态机：UI-01/02/03/04（滚轮、右键、ESC 返回、hover 预选）——纯输入/状态，Godot 不会自动解决。
- 消息/文字/布局：UI-06/07/08/09（消息消失、名牌重叠、选项截断、缺名字）——需要 WOLF 的窗口/字体度量规则，Godot 的 Control 节点只能帮你摆放，不能替你理解 WOLF 的 101/102 语义。
- 游戏状态：UI-10/11（行动力、妹妹消失）——事件/变量/图层状态，和引擎语言无关。
- 渲染层/图层：UI-05/12/13（黄绿闪、方针面板、图层优先级）——可以用更清晰的层模型解决，但不必换语言。

**Godot 能改善的是“控件/布局工具链”，不能自动修 WOLF 事件逻辑和存档兼容。**

### 3. 迁移成本与时机

- 当前版本已经能跑通标题→新游戏→多日循环→战斗→H→存档，接近可交付；此时重写的机会成本最高。
- 真正值得迁移的信号是：**P0/P1 修完后，每轮仍持续产生新的结构性 UI/图层 bug，且现有 Rust 渲染层无法用清晰抽象表达**。现在还没到那一步。
- 建议设决策门槛：先按 `docs/UI_BUG_BACKLOG.md` 完成 UI-01..UI-08，观察修复后是否还频繁出现同类回归。如果修复速度明显快于新增 bug，就继续 Rust；如果每次都“补一个坏一个”，再评估混合方案。

## 如果一定要用 Godot：推荐混合，不推倒

可行路径（按推荐度）：

1. **只换表现层**：把 `wolf-game/wolf-vm/wolf-format` 做成 C ABI/staticlib/动态库，Godot 通过 GDExtension 调用核心；Godot 只负责窗口、输入、UI 布局和绘制。
   - 优点：保留全部格式/VM/存档/事件逻辑；UI 用 Control 节点、z-index、Container。
   - 成本：需要设计跨语言接口、纹理上传/图片槽同步、事件循环桥接；不是零成本。
2. **保留现有 Rust 引擎，抽离 UI 层**：不引入 Godot，先把当前 `wolf-cli` 的 UI 拆成“输入状态机 + 图层清单 + 布局器”，用截图回归驱动。这是当前最务实的路线。
3. **完整 Godot 重写**：不推荐，除非项目目标变成“重新做一个同人游戏”而不是“Rust 重写原版”。

## 当前建议

- **不迁移**；先把 `docs/UI_BUG_BACKLOG.md` 的 P0/P1 修完。
- 先补一层统一的 **input intent → UI state → draw layer list**，这是比换引擎更直接的治本手段。
- 每个 UI bug 修复必须带前后截图；如果连续出现同类层优先级问题，再评估是否把渲染层做成独立的 `wolf-present` crate，或走 Godot 表现层混合方案。
