## 0. 结论速览

### 0.1 type 编号 → 官方效果名（已验证，来自 Editor.exe 字符串表）

WOLF RPG Editor 3.735 的 Editor.exe 里，效果名是一张 **11 个连续的、u16 长度前缀的 UTF-16LE 字面量表**（条目之间**零间隙**，说明是 Delphi 的 const 数组，顺序即运行时 type id）。地址与内容如下（work/_p290_21_enum.py 逐条断言，任一字节不符即 AssertionError）：

| type | 文件偏移 | 长度 | 效果名（编辑器原文） | 本作条数 |
|---|---|---|---|---|
| 0 | 0xA847E0 | 5 | フラッシュ | 9 |
| 1 | 0xA847EC | 5 | カラー補正 | 61 |
| 2 | 0xA847F8 | 12 | 描画座標シフト[最終値] | 146 |
| 3 | 0xA84812 | 4 | シェイク | 250 |
| 4 | 0xA8481C | 3 | ズーム | 49 |
| 5 | 0xA84824 | 7 | 点滅A[明滅] | 94 |
| 6 | 0xA84838 | 12 | 点滅B[自動ﾌﾗｯｼｭ] | **0（本作未用）** |
| 7 | 0xA84852 | 9 | 自動拡大縮小[％] | 25 |
| 8 | 0xA84866 | 13 | 自動ﾊﾟﾀｰﾝ切替[1回] | 51 |
| 9 | 0xA84882 | 15 | 自動ﾊﾟﾀｰﾝ切替[ﾙｰﾌﾟ] | 104 |
| 10 | 0xA848A2 | 13 | 自動ﾊﾟﾀｰﾝ切替[往復] | 21 |
| ≥11 | 不在这张表里 | — | 明滅フラッシュ / 描画座標シフト2 / 拡大率補正 / 角度補正 / 不透明度補正 / 全エフェクト解除 / ピクチャのコピー / ID移動 / Zオーダー変更 / 変換系6種 / 動画系3種 | **0（本作未用）** |

三条关键事实：

1. **官方手册的条目顺序 ≠ type 编号**。手册「エフェクト」页把 明滅フラッシュ 放在 フラッシュ 后面，但表里 type 1 是 カラー補正。凡是想「按手册第 N 条 = type N」的推测都会错。
2. **type ≥ 11 的效果名在同一 EXE 的别处**（如 拡大率補正 在 0xA8EC7A/0xA8ECEE、角度補正 在 0xA8EC9A/0xA8ED00、不透明度補正 在 0xA8EE7E/0xA8EE9C、明滅フラッシュ 在 0xA8F23E/0xA8F250、Zオーダー 在 0xA9528E），编号未测；**本作一条都没用**（head 最大值 160 = type 10），所以不影响本作移植，但会影响通用运行时的完备性。
3. **カラー補正 在编辑器命令说明里显示为 [色調整]**（0xA8E0E4 区段的命令摘要串），列表名仍是 カラー補正 —— 两个名字指同一个 type 1。

### 0.2 每个 type 真正用几个参数（已验证，来自编辑器格式化串）

同一区段（0xA8E0E4）里有编辑器生成命令摘要用的格式化串，**数 %s 的个数就是该 type 实际吃掉的参数个数**（外加恒存的「処理時間」字段）：

    ■ピクチャエフェクト：
    [フラッシュ]  R%s/G%s/B%s  [%s]ﾌﾚｰﾑ
    [色調整]
    [描画座標ｼﾌﾄ(最終値)]  Xｼﾌﾄ %s / Yｼﾌﾄ %s [%s]ﾌﾚｰﾑ
    [シェイク] #Xｼｪｲｸ %s / Yｼｪｲｸ %s / %s回  [%s]ﾌﾚｰﾑ
    [ズーム]  中心X %s / 中心Y %s / %s％  [%s]ﾌﾚｰﾑ
    [点滅A(明滅)]  R%s/G%s/B%s  明滅間隔[%s]ﾌﾚｰﾑ
    [点滅B(自動ﾌﾗｯｼｭ)]  R%s/G%s/B%s  点滅間隔[%s]ﾌﾚｰﾑ
    [自動拡大縮小]  横%s％/縦%s％/ 休%sﾌﾚｰﾑ  拡縮時間[%s]ﾌﾚｰﾑ
    [自動ﾊﾟﾀｰﾝ切替(1回)] 開始ﾊﾟﾀｰﾝ[%s] → 終了ﾊﾟﾀｰﾝ[%s]  間隔[%s]ﾌﾚｰﾑ
    [自動ﾊﾟﾀｰﾝ切替(往復)] 開始ﾊﾟﾀｰﾝ[%s] ←→ 終了ﾊﾟﾀｰﾝ[%s]  間隔[%s]ﾌﾚｰﾑ

⇒ **自動パターン切替三兄弟只吃 2 个参数**（始パタ / 終パタ），第三个参数位（args[6]）**引擎根本不用**；本作在这三位上留给的值（type 8 的 50/0、type 9/10 的 0）是残留垃圾。
⇒ **カラー補正 的格式化串一个 %s 都没有** —— 它没有「処理時間」参与语义（瞬时生效、永久保持），本作 type 1 的 dur 值（0 或 1）是无关噪声。
⇒ シェイク 的第三参数是 **回数**（不是 yado.tk 说的「1回処理時間」；官方手册「指定回数だけピクチャを揺らします」「10万回以上にすると無限」为准，yado.tk 错）。

### 0.3 参数布局（已验证）

    args[0]  head      head>>4 = type（§0.1）；head&0xF 在 810/810 里恒为 0
    args[1]  処理時間  帧数。语义随 type 变（§0.4 表最后一列）
    args[2]  picA      图片番号（起点，可为 magic：1600021 = 自身変数#21）
    args[3]  picB      图片番号（终点），**与 picA 一起构成闭区间范围**（§0.4）
    args[4]  v1        ┐
    args[5]  v2        ├ 三个参数，含义随 type 变（§0.4）
    args[6]  v3        ┘

    stringArgs 恒为空（810/810 条 s = []）；have_route 恒 0

**magic number 求值**（与 121/122/124 同一套寻址）：0..999999 字面量；1600000+n = 自身変数 #n；2000000+n = 通常変数；9000000+n = システム変数。实测 picA/picB 出现 1600021、1600026、1600040/1600041、1600011/1600012、1600051/1600052 等；v1..v3 也大量引用自身変数（§1.2）。

### 0.4 ★「□～□」是图片番号范围，不是「A 图 → B 图」（已验证）

官方手册 work/_effect_manual.txt 第 9 行原文：

    - ピクチャに対するエフェクト （□～□　の欄にピクチャ番号を指定してください）

⇒ args[2] 与 args[3] 是**区间的两端**（闭区间 [picA, picB]），picA == picB 时就是单张图。三条数据侧佐证：

| 佐证 | 内容 |
|---|---|
| 「全カーソル」注释 | CE85 pc510 `290 [16, 0, 1600021, 1600026, -100, -100, -100]`，作者注释写「全カーソルの色を消去」；一次命中 self21～self26 共 6 张光标图，只有区间语义才能解释「全部」 |
| 缩放成对出现 | type 4（ズーム）49 条里 **43 条 arg3 = arg2 + 1**，且像 (1200,1201)、(1202,1203)、(1204,1205) 这种「按钮底图 + 按钮文字」成对缩放；实测 150 确实分别画了 1200（349 次）和 1201（32 次） |
| 场景整体压暗 | type 5 有 16 条 `290 [80, 0, 390, 500, -50, -50, -50]`；实测 [390,500] 区间内 150 画过的图片号有 **72 个**，即一次把整幕 CG 压暗 |

⇒ **renderer 必须对 [picA, picB] 内所有「使用中」的图片逐张施加该效果**，只对 picA 施加会漏掉一半画面。
⇒ 反向区间只有 1 条（CE94 pc616 `290 [32, 0, 1600021, 1600013, 1600011, 0, 0]`，lo > hi）。引擎行为未知（推测交换或视为空），实现里建议「lo > hi 时交换」并记一条警告。

### 1.3 官方手册逐条原文（已验证，curl 抓取）

    + フラッシュ … 指定した赤・緑・青の値をピクチャの「カラー」に加算して1回だけフラッシュします。±200までの値に対応。
    + カラー補正 … 指定した赤・緑・青の値だけピクチャの「カラー」に加算します。±200までの値に対応。
    + 描画座標シフト[最終値] … 指定したX、Y値だけ、ピクチャの描画座標をずらします。単純に最終値をシフトさせるものです。
    + シェイク … 指定したX、Yの移動分で、指定回数だけピクチャを揺らします。「処理時間」フレームが短いほど、高速に振動します。10万回以上にすると無限になります。
    + ズーム … 指定したX、Y座標を中心に、指定した拡大率でピクチャをズームします。
    + 点滅A[明滅] … 指定したRGB分（最大±200）の差だけ、指定フレームでカラー変更による明滅（変化前、変化後、と交互に変化する）を繰り返します。「RGB値全てを０に設定する」か、または「フレーム数を０にする」と、点滅は停止します。
    + 点滅B[自動ﾌﾗｯｼｭ] … 指定したRGB（最大±200）の±分だけ、指定フレームでカラー変更によるフラッシュ（ウェイトせずに変化してから元に戻っていく）を繰り返します。…（停止条件同文）
    + 自動拡大縮小[％] … 指定した縦・横の拡大率の±値分だけ、指定フレームでピクチャを拡大縮小します。1回の拡縮後、休フレームだけ一時停止します。「鼓動」をイメージすると分かりやすいと思います。
    + 自動ﾊﾟﾀｰﾝ切替[1回] … 指定した開始パターン～終了パターンまで、パターン番号を1ずつ指定フレーム間隔で切り替えます。一回分のパターン切り替えが終わったら、ピクチャ側で設定された元のパターン番号に戻ります。
    + 自動ﾊﾟﾀｰﾝ切替[ループ] … 指定した開始パターン～終了パターンまで、パターン番号を1ずつ指定フレーム間隔で切り替えます。終了パターンまで切り替わったら、また開始パターンに戻ってループします。
    + 自動ﾊﾟﾀｰﾝ切替[往復] … 指定した開始パターン～終了パターンまで、パターン番号を1ずつ指定フレーム間隔で切り替えます。終了パターンまで切り替わると、開始パターンまで1ずつ戻り、ループします。

另外三条全局约束（同页）：

1. **效果与 150 完全独立**：「ピクチャに対するエフェクトは、「ピクチャ」処理で指定した内容とは独立して処理されます」；「座標シフトを行うと、ピクチャ処理で指定したX、Y座標＋座標シフト分のX、Y座標に描画され続けます。これは座標シフト分のX、Y値を0に戻すか、ピクチャを消去するまで有効です」。
2. **效果不会被「変数操作＋」读到**：「全ての「エフェクト」コマンドは、「変数操作＋」で取得される値には影響を与えません」—— 只有 124 的 0x4000（带补正）才把 shift 叠上去。
3. **カラー被夹在 0..200**：「「フラッシュ」や「色調の加算」は、「ピクチャ」処理時のカラー「0～200」の範囲を超えて色調が変わることはありません」⇒ 无论怎么叠加，有效颜色的百分率 p ∈ [0, 200]，100 = 原色。

## 2. 逐类型语义

### 2.1 type 3 —— シェイク（已验证）

- 250 条，是本作第二多的类型。処理時間 **15 帧占 163 条**（= 一次往返的帧数），另有 2/4/30/50 等。
- 参数：`v1 = シェイクX`、`v2 = シェイクY`（位移幅度，像素）、`v3 = 回数`。
- 实测 (X,Y) 组合：`(0,2)`×132、`(0,1)`×42、`(6,0)`×14、`(8,0)`×12、`(0,0)`×11、`(7,0)`×6、`(2,0)`×4、`(0,8)`×4 ⇒ **绝大多数是「竖直方向 1~2 px 的轻微抖动」**（立絵/演出时的「颤抖」）。
- 回数分布：`99999`×124（正好卡在「10万回以上 = 无限」之下）、`999`×52、`3`×36、`9999`×8、`8`×10、`0`×7、`999999`×2（= 真的无限）。
- 典型用法：
  - ev241「┣ターン開始処理」pc219..222 的**阶梯式震动**：`[48,2,3010,3010,6,0,3]` → `[48,3,3020,3020,8,0,3]` → `[48,4,3030,3030,8,0,3]` → `[48,4,3040,3040,7,0,3]`，然后 `180[20]` 等待 —— 每次 (X=6/8/8/7, Y=0, 回数=3)，処理時間 2/3/4/4 帧，即**越摇越快、越摇越大**的受击表现。
  - ev452（41 条）与 SampleMapA:ev15（36 条）是「持续微抖」的常客（`(0,2,99999)` 一族）。
- **实现模型**（高置信）：持续时间 = `回数 × 処理時間` 帧；每 `処理時間` 帧把绘制偏移翻转一次符号（+X/+Y → −X/−Y），或在该区间内取正弦；`回数 ≥ 100000` ⇒ 永不结束（本作 2 条 999999）。`v1=v2=0` 的 11 条等价于「空转计时器」，无害。
- **未确认**：抖动是「严格交替符号」还是「每帧在 [−X, X] 内随机」（原版可能用随机 ± 以求自然）；两者的可见差异很小，建议先用交替符号，视觉不对再改随机。

### 2.2 type 1 —— カラー補正（已验证；初版误标为「点滅复位/停止」）

- 61 条（公共事件 13 + SampleMapA:ev8 一处 48 条）。
- 参数：`v1..v3 = 赤/緑/青 的加算量`，±200。**処理時間 不参与语义**（§0.2：该 type 的摘要格式串一个 %s 都没有）；本作 dur 值是 0 或 1 的噪声。
- 语义（官方）：「指定した赤・緑・青の値だけピクチャの「カラー」に加算します」⇒ 给该图的カラー加一个**持续存在的加算项**，直到图片被消除或被再次指令覆盖。
- **关键用法（证明它必须实现成「设置」而不是「累加」）**：SampleMapA:ev8 的悬停高亮惯用法

      pc39  290 [16, 1, 3200, 3200, 25, 25, 25]   ← 被选中的选项：カラー +25
      pc40  290 [16, 1, 3201, 3201,  0,  0,  0]   ← 上一个被选中的：复位
      pc41  150 [16842753, …, 0, 0, 0, 1, 64, …]
      切到下一项时反过来再发一对（pc95/96 同形）

  ⇒ 如果引擎把 RGB **累加**到某个累加器上，(0,0,0) 就什么都清不掉，悬停几次后光标会越来越亮 —— 而全库**没有任何一条 `全エフェクト解除`（type ≥ 11 一条都没有，见 §0.1）**可用于补救。所以引擎的真实行为是：**把该图的「カラー補正项」赋成指定值（后写覆盖）**，渲染时再把这个项加到基色上。手册说的「加算」指的是「渲染时加到基色」，不是「累加到上一次的补正」。
- 其他用法：ev85 pc510 `(-100,-100,-100)` 配注释「全カーソルの色を消去」（范围 self21～self26，见 §0.4）⇒ 全部压成黑色；ev178 用 `(80,-30,-30)` / `(-30,-30,80)` / `(-30,80,-30)` / `(40,40,-30)` 给光标染红/蓝/绿/橙。
- **实现要点**：`pic.color_corr: [i32;3]`（默认 0），type 1 直接赋值；渲染时 `p = clamp(100 + corr, 0, 200)`。

### 2.3 type 2 —— 描画座標シフト[最終値]（已验证）

- 146 条，処理時間 124 条为 **0**（= 立即取最终值），另有 3 / 5 / 3000。
- `v1/v2 = シフトX / シフトY`，几乎都是自身変数引用：`(self11,self12,0)`×15、`(self70,self71,0)`×12、`(self72,self73,0)`×10、`(self51,self52,0)`×9 —— **成对的 self 变量 = X / Y**。`v3` 恒 0（未用）。

- **未确认**：两条 `処理時間=3000` 的样本，是否意味着「3000 帧内线性滑到目标」—— 官方说「単純に最終値をシフトさせる」，倾向仍然是即时，dur 只是编辑器遗留字段。

### 2.4 type 4 —— ズーム（已验证；初版误标为「图片切换 tween」）

- 49 条，処理時間 **恒 5 帧**。
- 参数：`v1 = 中心X`（**49/49 恒为 512** = 1024 屏宽一半）、`v2 = 中心Y`（200/250/300/350/400/450）、`v3 = 拡大率 %`（100 ×32、105 ×17）。

- 语义（官方）：以 (中心X, 中心Y) 为中心按指定百分比缩放该图（组），`処理時間` 帧内到达；结束方式是**同中心再发一次拡大率 100**。

### 2.5 type 0 —— フラッシュ（已验证）

- 9 条，処理時間 **恒 25 帧**，picA == picB 9/9，图片号全为 self21（当前窗口/立绘）。

- **未确认**：`-100` 是「该通道不抬」的哨兵，还是「压暗 100」（因为 (200,-100,-100) 只留红通道亮 ⇒ 更像是**绝对值**：把 RGB 设成 200/−100/−100 再回落；负值在 0..200 域里会被夹到 0）⇒ 实现建议：`target = clamp(100 + Δ)`，回落用线性。

### 2.6 type 5 —— 点滅A[明滅]（已验证；初版误标为点滅B）

### 2.7 type 7 —— 自動拡大縮小[％]（已验证；初版未确认）

- 25 条。処理時間（= 拡縮時間，单程帧数）：10 × 8、20 × 6、15 × 5、0 × 5、self64 × 1。
- 参数：`v1 = 横％±`、`v2 = 縦％±`、`v3 = 休フレーム`。
- **决定性证据**：`v1 == v2` 在 **25/25** 条成立（因为「鼓動」是等比缩放），且编辑器摘要串有 **四个 %s**（`横%s％/縦%s％/ 休%sﾌﾚｰﾑ  拡縮時間[%s]ﾌﾚｰﾑ`）= 3 个参数 + 1 个処理時間，与实测字段一一对应。
- 实测组合：`(8,8,60)`×3、`(12,12,40)`×2、`(10,10,40)`×2、`(6,6,80)`×2、`(5,5,80)`×2、`(50,50,0)`、`(10,10,10)` 等 ⇒ 幅度 5~50%，休息 0~80 帧。
- 语义（官方）：「指定した縦・横の拡大率の±値分だけ、指定フレームでピクチャを拡大縮小します。1回の拡縮後、休フレームだけ一時停止します」⇒ 一个周期 = `拡縮時間`（→ +p%）+ `拡縮時間`（→ 0%）+ `休フレーム`（静止），无限重复。
- 用法：ev339（18 条，图片 6100 = 立絵）、ev270（6 条）、ev326（1 条）。
- **实现要点**：`scale = base × (1 + amp × tri(t))`，`tri` 为 0→1→0 的三角波；`休フレーム` 期间 scale 回 base。

### 2.8 type 8 / 9 / 10 —— 自動パターン切替[1回 / ループ / 往復]（已验证；初版未确认）

- 条数 51 / 104 / 21。参数：`v1 = 始パターン`、`v2 = 終パターン`、**`v3` 引擎不用**（§0.2）。`処理時間 = 間隔`（每格帧数，0 = 停止）。
- 语义（官方逐条）：把图片的**パターン番号**从 始パターン 起，每 `間隔` 帧 +1，直到 終パターン；三种收尾方式：
  - **1回**（type 8）：跑完一轮后**回到 150 里设定的原始パターン番号**；
  - **ループ**（type 9）：回到 始パターン 继续；
  - **往復**（type 10）：从 終パターン 逐格退回 始パターン，再重复。
- 实测佐证这个「帧动画驱动」的语义：
  - type 8 全在战斗侧：图片 5000（= `BattleEffect/[Attack]Slash01_panop.png`，28 条）、500/501、81；`v2`（終パタ）5~30 正是斩击序列的帧数；`処理時間` 2~4 帧 ⇒ 斩击动画高速播放。ev239 pc765 `[128,3,5000,5000,1,5,50]` 紧跟 `150[3150080, 5000, …]` 然后 `180[15]`。
  - type 9（ループ）图片 10000（65 条）/10100，`(始,終) = (1,2)` 占 72 条，`間隔 30` 帧 ⇒ 两帧循环呼吸/闪烁（约 0.5 s 换一帧）。
  - type 10（往復）图片 14/1000/1015/2103，`v1 ∈ {1,2}`、`間隔 0/10/15/20/30`。
- **实现要点**：这三个 type 不改颜色、不改坐标，只改 **`pic.pattern`**（150 的 パターン番号）。所以 renderer 必须把「当前显示的パターン」从 150 的静态值里分离出来，效果层驱动它；`1回` 结束时把 pattern 复位成 150 的值。

           argc = 11  ⇒  结束于 idx10（BLEND），idx15..17 不存在

- 全库（550 公共事件 + 9 张地图）**0 条** 150 画图片番号 12001；唯一绘制点就是这个地图事件。
- ⇒ **222 的色调不可能由 150 带来**，只能是 pc91 的 290 type 5。

### 3.5 有效颜色的取值范围（已验证，官方原文）

官方：「「フラッシュ」や「色調の加算」は、「ピクチャ」処理時のカラー「0～200」の範囲を超えて色調が変わることはありません」⇒ 无论 150 的カラー与 290 的加算怎么叠，**最终有效百分率 p 被夹在 [0, 200]**，100 = 原色。实现里 `p = clamp(base + corr + effect, 0, 200)` 即可，不必担心溢出成负色。

## 4. 222 / 188 的成因判定（核心）

### 4.1 已测事实

|---|---|
| 图 | `SystemFile/Button01.png`，606×35，绘制在 (512, 520) 居中锚点（实测最佳偏移 (209,502) ⇒ 无位移） |
| 混合方式 | **RGB 逐通道乘以 k/255，alpha 完全不变**（alpha=191 的 texel 在 (246,503) 两侧读数都是 63；alpha=0 的 texel 完全一致） |
| k（截图 full_21_21_35.png） | **222**（69.5% 的采样；223 ×2745 / 221 ×2115 / 220 ×873 / 224 ×414 属重采样噪声） |
| k（截图 full_21_22_48.png，同位置同一张图） | **188**（78.5%） |

| 其余 6 张截图 | 找不到横幅（免责声明 / logo / 无横幅时刻） |

### 4.2 为什么这必须是「周期性渐变」（决定性推理）

`290` 在 TitleMap:ev2 里位于循环**之前**，只执行一次：

    pc90  150 [4096, 12001, …]                       画横幅
    pc91  290 [80, 30, 12001, 12001, -50, -50, -50]  ← 只执行一次
    pc92  180 [20]
    pc93  170          ← 循环开始
    pc94  180 [1]
    pc95  …键输入…      pc99/102/105 跳标签 A
    pc109 498          ← 循环结束
    pc110 212 A

- 若效果是**一次性**的（fade / フラッシュ：执行 → 变化 → 回到原位），那么帧 60（≈1 秒）之后与帧 4000（≈73 秒）之后**都应该是同一个终值**。
- 实测两张截图拿到的是 **222 与 188 两个不同的中间值**，且都不等于两端（255 = 100%，128 = 50%）。
- ⇒ 只有**周期性、连续渐变**才能解释：每帧取 [50, 100] 之间的某个值。

### 4.3 A 还是 B —— 已由编辑器枚举定死：**type 5 = 点滅A[明滅]**（已验证）

初版（vm-spec）曾据「点滅A 若是瞬间切换两端，k 只会取 255/128 两个离散值」推断 type 5 = 点滅B。**这个前提是错的**：官方对点滅A 的原文是「指定したRGB分（最大±200）の差だけ、**指定フレームで**カラー変更による明滅（变化前、变化后、と交互に变化する）を繰り返します」—— 「指定フレームで」意味着**变化本身要花指定帧数**，即 100 → 100+Δ 是**逐帧渐变**，不是瞬间跳变。所以 A 同样是连续三角波，k 取中间值完全正常。

而 type 编号不再需要推断：Editor.exe 的枚举表里 **id 5 = 点滅A[明滅]**、id 6 = 点滅B（本作 0 条）（§0.1，逐字节断言）。

⇒ **结论**：type 5 = 点滅A；模型为 `p(t) = 100 + Δ × tri(t)`，`tri` 以 `処理時間` 帧为单程的 0→1→0 三角波（周期 = 2×処理時間 = 60 帧），Δ = −50 ⇒ p ∈ [50, 100]。实测 p = 87.06 / 73.73 都落在这个区间内 ✓。

### 4.4 数值链（已验证的部分 + 推断的部分）

    カラー百分率 p  ： 100 = 中性；p = 100 + Δ（Δ = −50 ⇒ p ∈ [50, 100]），引擎夹在 [0, 200]
    逐通道字节       ： byte = clamp(round(p * 255 / 100), 0, 255)     ← 需 p 为浮点，p=50 → 128
    绘制            ： dst = round(src * byte / 255)  （RGB 同乘，alpha 不参与）  ← 已验证
    反解            ： k = 222 ⇒ p = 87.06；k = 188 ⇒ p = 73.73      ← 都 ∈ [50, 100] ✓

- `p = 50 → byte = 128` 与「实测最小的 k 是 188、从未出现 128」一致（两张截图都只是**中途**采样；三角波每 60 帧走完 50↔100，落在极值附近的概率低）。
- **未确认**：`p > 100`（变亮）的混合方式 —— 实测样本里没出现过大于 255 的通道。官方只说「全部 200 就变白」⇒ 推测是**加算并夹取**（`dst = clamp(src + (p−100)/100 × 255)`），**不要**用乘法实现（乘法永远到不了白）。

### 5.1 数据结构（把「效果层」与 150 的基值分开）

### 5.2 op_290 分派（含本作全部 11 个 type）

    fn op_290(pics: &mut PictureTable, cmd, vm) {
        let kind = cmd.head >> 4;
        let dur  = vm.eval(cmd.args[1]) as i32;
        let lo   = vm.eval_picture(cmd.args[2]);   // 起点（可为 magic）
        let hi   = vm.eval_picture(cmd.args[3]);   // 终点
        let (lo, hi) = if lo <= hi { (lo, hi) } else { (hi, lo) };  // 反向区间容错
        let v = [vm.eval(cmd.args[4]) as i32,
                 vm.eval(cmd.args[5]) as i32,
                 vm.eval(cmd.args[6]) as i32];

        // 范围语义：对 [lo, hi] 内每张「使用中」的图片逐张施加（§0.4）
        for id in pics.used_ids_in(lo, hi) {
            let pic = pics.get_mut(id);
            match kind {
                0 => pic.set_flash(v, dur.max(1)),                     // フラッシュ：一次，dur 内回落
                1 => pic.color_corr = v,                               // カラー補正：赋值（非累加）
                2 => pic.shift = (v[0], v[1]),                         // 描画座標シフト[最終値]
                3 => {                                                  // シェイク
                    if v[2] == 0 { pic.shake = None; }
                    else { pic.shake = Some(ShakeFx { x: v[0], y: v[1], count: v[2],
                                                      period: dur.max(1), elapsed: 0 }) }
                }
                4 => pic.zoom = Some(ZoomState { center: (v[0], v[1]),
                                                 scale: v[2] as f32 / 100.0 }),  // ズーム
                5 => {                                                  // 点滅A[明滅]
                    if dur <= 0 || v == [0, 0, 0] { pic.remove_color_fx(5); }
                    else { pic.upsert_color_fx(ColorFx { kind: 5, rgb: v,
                                                        period: dur, elapsed: 0 }) }
                }
                6 => { /* 点滅B：本作 0 条，按「瞬变后衰减」实现即可（不影响本作） */ }
                7 => {                                                  // 自動拡大縮小[％]
                    if dur <= 0 { pic.breath = None; }
                    else { pic.breath = Some(BreathFx { amp: [v[0], v[1]], rest: v[2],
                                                        period: dur, elapsed: 0 }) }
                }
                8 | 9 | 10 => {                                         // 自動パターン切替
                    if dur <= 0 { pic.pattern_fx = None; }
                    else { pic.pattern_fx = Some(PatternFx {
                        kind: kind, from: v[0], to: v[1], interval: dur,
                        cur: v[0], forward: true, elapsed: 0, done: false }) }
                }
                _ => { log_warn(unknown_effect_type(kind)); }           // ≥ 11 本作未用
            }
        }
    }

### 5.3 每帧 tick（60 fps）

    fn tick(pic: &mut PictureState) {
        // シェイク：每 period 帧翻转符号，回数用完即止；count >= 100000 永不结束
        if let Some(s) = &mut pic.shake {
            s.elapsed += 1;
            let half = s.elapsed / s.period;          // 第几次半周期
            let sign = if half % 2 == 0 { 1 } else { -1 };
            pic.render_shift = (s.x * sign, s.y * sign);
            if s.count < 100_000 && half >= s.count * 2 { pic.shake = None; pic.render_shift = (0, 0); }
        }
        // 自動拡大縮小：0→1→0 用时 period×1 + 休息 rest
        if let Some(b) = &mut pic.breath {
            b.elapsed += 1;
            let cycle = b.period + b.rest;
            let t = (b.elapsed % cycle) as f32;
            let k = if t < b.period as f32 { t / b.period as f32 } else { 0.0 };
            let tri = if k < 0.5 { k * 2.0 } else { (1.0 - k) * 2.0 };   // 或直接用 k，见未确认项
            pic.render_scale = (1.0 + b.amp[0] as f32 / 100.0 * tri,
                                1.0 + b.amp[1] as f32 / 100.0 * tri);
        }
        // 自動パターン切替：驱动 pic.render_pattern
        if let Some(p) = &mut pic.pattern_fx {
            p.elapsed += 1;
            if p.elapsed % p.interval == 0 && !p.done {
                match p.kind {
                    8 => { if p.cur == p.to { p.done = true; pic.render_pattern = pic.base_pattern; }
                           else { p.cur += 1 } }
                    9 => { p.cur = if p.cur == p.to { p.from } else { p.cur + 1 } }
                    10 => { if p.cur == p.to { p.forward = false }
                            else if p.cur == p.from { p.forward = true }
                            p.cur += if p.forward { 1 } else { -1 } }
                    _ => {}
                }
                if !p.done { pic.render_pattern = p.cur; }
            }
        }
        // 颜色类：三角波
        for fx in &mut pic.color_fx {
            fx.elapsed += 1;
            let t = (fx.elapsed % (fx.period * 2)) as f32 / (fx.period * 2) as f32;
            let tri = if t < 0.5 { t * 2.0 } else { (1.0 - t) * 2.0 };
            for i in 0..3 { pic.fx_tone[i] = fx.rgb[i] as f32 * tri; }
        }
    }

### 5.4 绘制时的有效颜色

    /// p = 百分率，100 = 中性，引擎夹在 [0, 200]（官方明文）
    fn effective_tone(pic: &PictureState, ch: usize) -> f32 {
        (pic.base_tone[ch] + pic.color_corr[ch] as f32 + pic.fx_tone[ch]).clamp(0.0, 200.0)
    }
    fn tone_byte(p: f32) -> u8 { (p * 255.0 / 100.0).round().clamp(0.0, 255.0) as u8 }

### 5.5 解析层要改的三处

1. **150**：`argc >= 18` 时读取 `args[15..17]` 作为 `base_tone`（百分率；缺省 100）。当前 `crates/wolf-game/src/picture.rs` 只解析到 `args[10]`（BLEND），长格式整段被丢弃。
2. **290**：实现成「写入 PictureState 的效果层」，**不要**改 150 设的字段；也**不要**让 124 的属性读取被效果污染（除非 124 带 `0x4000` 补正位）。
3. **290 的图片号是范围**：`args[2..4]` 要读成 `[lo, hi]` 闭区间并对区间内所有使用中的图片施加（§0.4）。当前若按「单张」实现，type 4（7 对按钮）、type 5 的整幕压暗、CE85 的「全カーソル」都会只作用到一半。
