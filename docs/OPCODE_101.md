> 适用对象：*Living With Sister Monochrome Fantasy*（Steam appid 2429860）
> 引擎：WOLF RPG Editor v3.x（Game.exe v2.20，`Sys115 = 220`）
> 数据源：`work/_ce_full.json`（550 公共事件）+ `work/maps_full.json`（9 个 .mps）
> 标记约定：**【已验证】** = 有字节级或统计级证据；**【未验证】** = 推断或缺乏运行期确认。

## 0. 一句话结论

`101` 是**阻塞型协程指令**：把一段带转义的文本按打字机节奏推进一个 **960×168** 的九宫格窗口
（左上 `(64,408)`、贴屏幕右下角），然后挂起本实例，直到玩家按決定／キャンセル键
（或文本里的 `\^` 让它在打完字后自己关）；关闭动画 **6 帧**。
窗口几何完全由 Sys1/Sys2/Sys5/Sys6 + 座標倍率（**rateX = 32、rateY = 24**）决定，
而全部 13,180 个 `101` 站点中**没有一个**在邻近指令里改写过这些系统变量【已验证】——
对重写者而言窗口几何是**常量**，不是变量。

命令本身极简：`argc = 0`、`strc = 1`，13,180 / 13,180 无一例外【已验证】。

## 2. 参数布局

| 槽位 | 含义 | 依据 |
| --- | --- | --- |
| `intArgs[0..]` | **不存在**（`argc` 恒 0） | 【已验证】13,180/13,180 |
| `stringArgs[0]` | 消息正文（UTF-8，含全部转义码与裸 LF） | WolfTL `Command::Text()` 返回 `m_stringArgs.at(0)`（docs/vendor/WolfTL-main/WolfTL/WolfRPG/Command.hpp:745 附近）【已验证】 |
| `stringArgs[1..]` | **不存在** | 【已验证】strc 恒 1 |

正文编码规则【已验证】：

- UTF-8；**换行是裸 `0x0A`**（编辑器里直接回车），不是 `\n` 转义 —— 全库 `\n` 转义仅 3 次，
  而裸 LF 出现在 4,442 条字符串里（其中 101 占 3,915）。**实现必须按 0x0A 切行。**
- 最大码点 U+FF5E，没有非 BMP 字符 ⇒「按 UTF-16 单位还是按码点算字数」在本作等价，
  可放心按 Unicode 标量计数。
- CR 出现 2,132 次（`\r` 语句 + 少量文本换行），渲染前应归一化。

执行语义【已验证：本项目 VM 已实现同样形状】：

    inst.pc += 1;                   // 先推进 PC（阻塞期间 PC 已指向下一条）
    inst.wait = WaitState::Message; // 本实例挂起
    yield Blocked;                  // 其它协程继续跑

关闭后从 `pc` 处继续。转义展开（`\v[n]`／`\cself[n]` 等）在**进入消息时一次性快照**，
不是每帧重读 —— `101` 之后改变量不会影响已显示的文本
【未验证：需逐帧仿真确认；但与 952 次 `\cself` 的用法一致（作者都在 101 之前设值）】。

## 3. 窗口几何（本文件最重要的量化结论）

### 3.1 两个座標倍率：rateX = 32、rateY = 24

`ev48 X[共]基本システム自動初期化` 在「新処理」分支（`Sys115 == 220`，本作走这条）里算：

    pc30  121 [1600025, 9000116, 32, 12288]   self[25] = Sys116 / 32     (0x3000 = 除法)
    pc31  121 [1600026, 9000117, 24, 12288]   self[26] = Sys117 / 24
    pc32  250 [18, 97, 0, 65536, 1600025]     DB[座標倍率X] ← self[25]
    pc33  250 [18, 98, 0, 65536, 1600026]     DB[座標倍率Y] ← self[26]

`Sys116/117 = 画面サイズX/Y = 1024/576`（Game.dat + 截图实测 1024×576）⇒ **rateX = 32、rateY = 24**。
独立闭合验证：`ev63` 自己又把 `32*rateX`、`24*rateY` 当「屏幕右下角坐标」写进 self[42]/self[43]
（pc38/pc39），要自洽必须 `32*rateX = 1024`、`24*rateY = 576` ⇒ 32 / 24。两条独立路径互证【已验证】。

> ⚠ `docs/OPCODE_102.md:250/260-264` 把这两个倍率读成「x10 缩放，本作取 10」，是错的（见 §10 C7/C8）。
> 倍率的正式名字是「座標倍率」；`(x10)` 只是 YADOT 老文档对旧版本的注记，本作数据里存的就是 32 / 24。

### 3.2 Sys1..Sys6 的初始化（`ev63 X[共]メッセージウィンドウ`）

YADOT 官方文档（`work/yado.txt:646-673`）直接抄出了 `ev63` 第 44~47 行的原作代码；
本作字节码与之对齐（数值取本作实测）：

| 指令 | 官方抄录 | 本作表达式 | 值 |
| --- | --- | --- | --- |
| pc44 | `Sys1 = 2 * CSelf88` | `2 * rateX` | **64** |
| pc45+46 | `Sys2 = 17 * CSelf89`；`Sys2 += CSelf89 / 10` | `17*rateY + rateY/10` | 408 + 2 = **410** |
| pc47 | `Sys3 = 16 * CSelf88` | `16 * rateX` | **512** |
| pc48 | `Sys4 = 8 * CSelf89`（YADOT 旧版写 7） | `8 * rateY` | **192** |
| pc49 | `Sys5 = 16 * CSelf88` | `16 * rateX` | **512** |
| pc50 | `Sys6 = 6 * CSelf89` | `6 * rateY` | **144** |

pc45/pc46 的字节码是 `121 [9000002, 1600089, 10, 12544]`（`12544 = 0x3100` ⇒ 复合 `+=`、二元除法），
与官方抄录的 `+= CSelf89 / 10` 完全一致 ⇒ 这同时是「0x3000 = 除法」的又一条铁证（见 §10 C7）。

### 3.3 窗口矩形 = (64,408) – (1024,576)

`ev63` 用 `150` 的**窗口型**（`type = (a0>>4)&7 = 4`）画窗口，参数映射
`[3]=宽 [4]=高 [7]=X [8]=Y`、锚点 `(a0>>12)&7`（0=左上、1=中心、4=右下）：

    pc90   150 [4160, 1600020, 5, 1600038, 1600039, 1, 255, 1600032, 1600033, 100, 0, 1600009]
           a0=0x1040 ⇒ type=4 cmd=0 anchor=1(中心)；宽=self[38]=960、高=self[39]=168
           中心 = (self[32]=512, self[33]=672)  ← 初次显示：整块在画面下方之外（672 > 576）
    pc93   150 [4198145, 1600020, 5, 0, 0, -1000000, -1000000, 1600030, 1600031, ...]
           a0=0x400f01 ⇒ anchor=0(左上)、宽高传 0 = 保持；位置 = (512, 480)   ← 开场滑入
    pc160  150 [4214545, 1600021, 5, 0, 0, -1000000, 255, 1600042, 1600043, ...]
           a0=0x404f11 ⇒ anchor=4(右下)；位置 = (self[42], self[43]) = (1024, 576)
           ⇒ 最终矩形 = (1024-960, 576-168) – (1024, 576)

⇒ **窗口 = 960×168，左上角 (64,408)，贴屏幕右下（右边距 0、下边距 0、左边距 64）**【已验证】。
自洽校验：`2*rateX = 64`、`17*rateY = 408`、`30*rateX = 960`、`7*rateY = 168` 四个数同时对上
⇒ 窗口矩形与 Sys1/Sys2 出自同一套倍率，不是巧合。

两条实现要点：

1. **文字原点 = (Sys1, Sys2) = (64, 410)**，比窗口顶边低 2 px（= 那一次 `rateY/10` 微调）：
   窗口顶边 = `17*rateY = 408`，文字原点 = `17*rateY + rateY/10 = 410`。
2. 窗口高度与字号无关（168 是 7 行倍率），**行容量另算**：
   `(168 - 上下留白) / (Sys8 + 6) ≈ 4~5 行`，与 YADOT「5 行以上会溢出」一致
   【已验证：行数与官方说法一致；留白像素未逐一核对】。

## 4. 脸图（顔グラフィック）

### 4.2 脸的尺寸与定位【已验证：ev63 算式】

    pc138 121 [1600057, 96, 1600088, 8192]   self[57] = 96 * rateX = 3072
    pc140 121 [1600057, 10, 0, 1024]         self[57] /= 10        ⇒ 307
    pc139/141 同法                           self[58] = 96 * rateY / 10 = 230
    pc160/161/162 150 [...]                  anchor=4(右下)，基准 = (self[42], self[43]) = (1024, 576)

⇒ **标准脸框 307×230 px，贴屏幕右下角**（与窗口同一锚点，因此脸压在窗口右下）。
另有倍率槽 self[23]（`250 [19,0,26,...]` 读入，strs 标注
`システム設定.メッセ—ジ 顔グラフィック倍率`，取值 0..4，**0 = 標準尺寸**）
【已验证 0 = 標準（pc132 的分支）；各档位具体像素倍率【未验证】】。

### 4.3 脸的「眨眼」是换图，不是换脸

`ev63` 用图片槽 19501+0..2 做 3 帧表情循环：`self[20]+1` 与 `self[20]+self[91]`
（`self[91] = 3`）之间轮播，`self[90] += 1` 之后 `self[90] %= self[91]`（pc164/165）
【已验证：字节码直读】。⇒ 实现上当成「同一张脸的 3 张差分图轮播」，与 Sys0 无关。

### 4.4 两种指定脸号的写法【已验证】

1. **系统变量法**（本作主流）：显示前写 `Sys0 = n`。
2. **文本首行法**：正文第一行写 `@n`（半角，后跟换行）。官方文档
   `work/yado.txt:590-593`：「文章設定の１行目に『@顔番号<改行>』を設定する方法」。
   本作实际出现 **20 次，全部 `@1`**（= 只画窗口、不画脸，用于旁白）【已验证】。

**关键坑点**：Sys0 是**一次性**的 —— 「1つ目の文章を表示して、3フレーム以上経つと、
顔グラフィックの設定が初期化されます」（`work/yado.txt:742` 附近）⇒ 每条消息都要重设，
不能靠「上一条设过就一直有效」。

### 4.5 本作实情：几乎没有逐句切脸

全库 Sys0 只有 **3 个写者**：`ev63` 自身 2 条（`[9000000,1,0,0]`，把脸重置为「ウィンドウのみ」）
与 `ev267` 1 条（`[9000000,1600000,0,0]`，把**调用方传入的 self[0]** 写进 Sys0 —— 切脸包装器）。
「101 之前 6 条指令内写 Sys0」的站点数 = **0 / 12,027**【已验证】
⇒ 本作靠 `ev267` 之类包装事件 + `@1` 文本控制脸；重写时**不要**假设每句都重设 Sys0。

## 7. 转义码（本作实到 / 全库）

「全库」= 所有 opcode 字符串里的次数，「101」= 只在 101 正文里的次数
【已验证：`work/_p101x.py`、`work/_p101y.py`】。字母类统计用 isalpha 会把 CJK 粘连项
（如 `\E嗯`）算进来，故字母类数值是**下界**。

| 码 | 语义（YADOT 官方） | 全库 | 101 | 影响字数 |
| --- | --- | --- | --- | --- |
| `\E` | 给后续文字加描边 | 3,677+ | 2,984+ | 否 |
| `\N` | 取消描边（**不是换行**） | 0 | 0 | — |
| `\f[n]` | 字号 = n（基本 = Sys8） | 2,472 | 196 | 否 |
| `\f+[n]` | 字号 += n | — | — | 否 |
| `\c[n]` | 字色 = System_DB[12] 第 n 行 | 1,740 | 520 | 否 |
| `\cself[n]` | 展开为「本公共事件 self 变量 n 的字符串形式」 | 952 | 113 | **是** |
| `\v[n]` | 展开为普通变量 n | 329 | 36 | 是 |
| `\s[n]` | 展开为字符串变量 n | 61 | — | 是 |
| `\ax[n]` | 绝对 X 坐标 = n | 34 | — | 否 |
| `\cdb[...]` | 展开为可変DB 的值 | 28 | — | 是 |
| `\A` | 抗锯齿开关（`\A+`／`\A-`） | 4 | — | 否 |
| `\r[文字,ルビ]` | ルビ（注音） | 2 | 2 | 否（ルビ另算） |
| `\>` | 瞬间显示（跳过打字机） | 77 | **71** | — |
| `\<` | 取消瞬间显示 | 1 | 0 | — |
| `\-[n]` | 字间距收紧 | 14 | 0 | — |
| `\.` | 0.25 秒等待 | 11 | 9 | — |
| `\^` | 显示完立即关窗 | 11 | 9 | — |
| `\!` | 句中按键等待 | 3 | 0 | — |
| `\n` | **不是换行**（仅 3 处数据误用） | 3 | 0 | — |
| 裸反斜杠 | 字面反斜杠 | 120 | — | 是（1 字） |

本作 101 **实际只用到**：`\E` `\f` `\c` `\cself` `\v` `\>` `\.` `\^` `\r`。
`\N` `\C` `\W` `\P` `\i` 在 101 里 **0 次**，而且 `\N`／`\C`／`\W`／`\P`
在官方特殊字符表里根本不是「换行／清屏／等待／暂停」码 —— 真实对应是 `\N`=取消描边、
`\wE[n]`=描边粗细、`\cE[n]`=描边色、`\cS[n]`=影色。**实现时不要给这几个字母编造语义。**

**嵌套**合法：`ev64 pc185` 的正文就是 `'\f[\cself[18]]\space[0]'`（`\f` 的参数本身是转义）。
YADOT 给出的优先级（内层只能放更低的）：
`\v` < `\v?` < `\self` < `\cself` < `\sys` < `\udb` < `\cdb` < `\sdb` < `\s` < `\sysS`
【已验证：官方原文】。嵌套应由**内向外**逐层替换，而不是正则一次扫完。

## 9. 协程语义（101 ↔ 172/173/99/180）

- `101` 阻塞**本实例**，不冻结整个 VM：`ev63` 自己就是被 101 的调用方拉起的公共事件，
  等待期间仍要每帧跑（`179 [1]` + `180 [1]` 的轮询环，pc182-190 与 pc205-213）【已验证字节码结构】。
- `172 BreakEvent`／`173 EraseEvent` 让实例立即结束；若它正卡在 101 里，消息窗口不会被擦
  （`ev63` 的擦除是它自己的 pc201-203）⇒ **重写时必须把「窗口擦除」挂在消息实例的清理路径上**，
  不能只挂在「关闭键」上【未验证：原作是否有此泄漏；属推断】。
- `99 Checkpoint` 是独立分支的起点标记，与 101 无关（101 前后 99 出现 0 次）。
- `180 Wait` 与 101 的区别：180 只等帧、不显示；101 等键。
- `105 ForceStopMessage`（文章の強制中断）在本作 **0 次** ⇒ 可不实现；语义（YADOT）是
  「立刻关掉当前消息、让卡在 101 的实例继续」【已验证 0 次；语义来自官方文档】。

窗口显示期间引擎做的三件事（重写必须体现）：
`Sys12 = 1`（表示中）、`Sys0` 的 3 帧后复位、`Sys9`／`Sys10` 的恢复（关窗后 Sys10 回 9）
【数值已验证】。
