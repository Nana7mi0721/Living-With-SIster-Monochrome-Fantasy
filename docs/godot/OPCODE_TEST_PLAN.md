# 高频指令（Top 5 Opcode）执行与测试计划（M0/M1）

> 状态：**现行 / 冻结**
> 对应规划：`docs/godot/PLAN.md` §3.3 退出标准 7；为 M1 EventVM 核心研发提供明确的测试规约与边界定义。
> 涉及指令：`401 ChoiceCase`、`210 CommonEvent`、`121 SetVariable`、`111 VariableCondition`、`180 Wait`。
> 覆盖规模：合计 69,720 条指令，占全游戏 139,273 条真实指令的 **50.1%**。

---

## 1. 总览与测试分级

本计划将高频指令的测试划分为三个执行层级：
1. **L1 纯单元测试（Unit Tests）**：纯 C# 算法与解码测试，不依赖 Godot 场景树，针对 32 位有符号溢出、位域掩码、除零保护、参数解码做穷尽边界断言。
2. **L2 状态机微测试（Micro VM Tests）**：单协程/单事件在内存中的步进与 PC 转移，验证条件分支跳转、栈帧压出、协程挂起与唤醒。
3. **L3 Oracle 对拍测试（Trace Alignment）**：基于 `oracle/diff_trace.py` 与真实游戏公共事件（如 CE42 标题画面、CE48 卧室初始化），逐步对齐 `step / pc / op / vars / effects`。

## 2. Opcode 121: SetVariable（変数操作，17,258 次）

### 2.1 规范与二进制布局
- 参数长度：`argc ∈ {4, 5}`；`strc = 0`。
- `arg[0]`：写入目标地址（Magic 寻址：`2000000..` 常规变量，`1000000..` Self 变量，`9000000..` 系统变量）。
- `arg[1]`：操作数 A（Magic 寻址或字面量）。
- `arg[2]`：操作数 B（Magic 寻址或字面量）。
- `arg[3]`：运算符复合位域：
  - `(arg[3] >> 12) & 0xF`：二元运算操作符（`0: +`, `1: -`, `2: *`, `3: /`, `4: !`, `5: &`, `6: rand(A, B)`, `7: |`, `8: ^`, `9: <<`）。
  - `arg[3] & 0x0F00`：复合赋值操作符（`0x000: =`, `0x100: +=`, `0x200: -=`, `0x300: *=`, `0x400: /=`, `0x500: %=`, `0x800: abs` 等）。
  - `arg[3] & 0x10000`：范围赋值置位（置位时存在 `arg[4]`）。
- `arg[4]`：连续目标末端偏移（包含式：作用于 `arg[0] ..= arg[0] + arg[4]`）。

### 2.2 关键边界与边缘用例（DoD）
1. **32 位整数环绕溢出（Wrapping Overflow）**：
   - 必须使用 C# `unchecked` 块进行 32 位有符号运算：
     - `int.MaxValue + 1 == int.MinValue`。
     - `int.MinValue - 1 == int.MaxValue`。
     - 禁止抛出 `OverflowException`。
2. **除零与取模零保护**：
   - 当 `b == 0` 时，除法与取模不得抛出 `DivideByZeroException`。
   - 规范行为：除零时保持当前变量原值不变，记录 warning 日志。
3. **随机数区间（`0x6000`）**：
   - `rand(min, max)` 必须包含双端点 `[min, max]`。
   - 当 `min > max` 时自动互换；当 `min == max` 时恒等返回 `min`。
   - 使用确定性 MINSTD PRNG，确保对拍可重现。
4. **低 8 位未知掩码过滤**：
   - 必须先做 `mask = arg[3] & 0xFF00`，过滤低 8 位冗余标志（194 条历史残留）。
5. **范围写入（`arg[4]` 存在）**：
   - 包含式遍历 `0..=arg[4]`，依次计算并写入目标槽位（如 CE94 pc87 `[1600022, 10, 0, 66560, 3]` 一次更新 4 个坐标槽）。

## 3. Opcode 111: VariableCondition（条件分岐，10,743 次）

### 3.1 规范与二进制布局
- 参数长度：`argc = 1 + 3 * condCount`；`strc = 0`。
- `arg[0]`：位域：
  - `arg[0] & 0x0F`：条件数量 `condCount ∈ {1, 2, 3, 4}`。
  - `arg[0] & 0x10`：是否存在 Else 分支（`use_else_branch`）。
- `arg[1 + 3i .. 3 + 3i]`：第 i 个条件三元组 `[variable, value, operator]`：
  - `operator`: `0: >`, `1: >=`, `2: ==`, `3: <=`, `4: <`, `5: !=`, `6: &`（按位与非零）。
  - 超出枚举值（17/18/19 容错）：作为 `==` 兜底并输出 Warning。

### 3.2 关键边界与边缘用例（DoD）
1. **短路与多条件判定**：
   - 顺序求值各个条件；第一个为 `true` 的分支立即命中，执行该分支体。
   - 执行完毕后跳跃到配对的 `499 BranchEnd` 之后。
2. **Else 分支执行**：
   - 所有条件均为 `false` 时，若 `use_else_branch` 置位，跳入 `420 ElseCase`；若无 Else 分支，直接跳至 `499` 之后。
3. **跳转表预编译**：
   - 加载阶段在 Python 编译期或 C# 启动期预先解析配对栈，生成静态跳转目标 `target_pc`，运行时 O(1) 转移。

## 4. Opcode 210: CommonEvent（公共事件调用，18,468 次）

### 4.1 规范与二进制布局
- 参数长度：`argc = 2 + nc + rv`。
- `arg[0]`：事件 ID（带命名空间）：
  - `500000 + id`：公共事件 `id`。
  - `600000 + id`：系统公共事件 `id`（同属 0..549 范围）。
  - `>= 1000000`：动态 Magic 变量寻址（运行期求值获取真正事件 ID）。
- `arg[1]`：`param_status` 位域：
  - `raw & 0x0F`：数值参数个数 `nc`。
  - `(raw >> 24) & 0x01`：是否存在返回值目标 `rv`。
- `arg[2 .. 2+nc)`：传参值列表。
- `arg[2+nc]`：返回值写入地址（当 `rv == 1` 时存在）。

### 4.2 关键边界与边缘用例（DoD）
1. **协程模型而非直接栈调用**：
   - 调用公共事件时创建独立的子事件协程实例，分配独立的 Self 变量空间（`1000000..1999999`）。
   - 父协程挂起进入 `WaitingForChild` 状态，不推进父 PC。
2. **动态事件调用（Magic Variable as ID）**：
   - 动态变量求值后提取基址，若求值结果落在 0..549 或 500000+，正确派发。
3. **返回值写回**：
   - 子事件正常结束或执行 `172 BreakEvent` 时，若指定了返回值槽位，从子事件的 `ReturnRegister` 取出并写回父级指定地址。
4. **递归防护与深度限制**：
   - 允许菜单类自递归调用，最大调用深度设为 64；超出时抛出明确的递归失控异常并断点。

## 5. Opcode 401: ChoiceCase（分支体标记，18,555 次）

### 5.1 规范与二进制布局
- 参数长度：`argc = 1`。
- `arg[0]`：分支序号（**1-based**，`1, 2, 3...`）。

### 5.2 关键边界与边缘用例（DoD）
1. **非可执行语义**：
   - `401` 在字节码中是分支体的开头标号，不是运行时计算指令。
   - 顺序执行流遇到 `401` 时，意味着「上一分支体执行完毕」，必须强制跳转至外层块末尾的 `499 BranchEnd`。
2. **父块类型区别**：
   - 在 `111 VariableCondition` 块下，序号与条件序号 1:1 对应（第 1 条件对应 case 1）。
   - 在 `102 Choices` 块下，序号从 2 开始对应（选项 1 为 case 2，见规范）。预编译跳转表必须严格核对映射。

## 6. Opcode 180: Wait（等待时钟帧，4,696 次）

### 6.1 规范与二进制布局
- 参数长度：`argc = 1`。
- `arg[0]`：等待帧数（60fps 逻辑时钟帧，支持 Magic 变量）。

### 6.2 关键边界与边缘用例（DoD）
1. **`arg[0] == 1` 的让步语义**：
   - 出现 1,172 次。必须挂起当前协程至「本逻辑帧末尾/下一帧开始」，让出调度权给同帧其他并行协程，严禁优化为 0 帧空转。
2. **动态变量帧数**：
   - 运行时通过 `eval_magic(arg[0])` 计算实际等待帧数；计算值 `<= 0` 时立即跳过或当帧继续。
3. **确定性帧进驱动**：
   - 计时器挂钩于 EventVM 的逻辑时钟（每次 60fps tick 递减 1），不依赖任何宿主墙上时钟或浮点 delta。
