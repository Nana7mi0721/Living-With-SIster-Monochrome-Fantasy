## 1. 结论摘要

1. **已证实**：「开始咯」对应 CE42 选项索引 0、`401` 分支 2，唯一动作是 `130 [-1,60,34,3,1]` 传送到 `Map003`。该分支没有 `210` CE14 调用、没有 `220/221` 存档/读档指令，也没有按 `HasSave` 或存档存在性分支的脚本。
2. **已证实**：「继续咯」对应索引 1、`401` 分支 3，先等待 12 帧，再执行 `210 [500014,1,-1]`。`500014` 是公共事件 14 的命名空间编码，`1` 是“一个数值参数”，`-1` 才是 CE14 的参数；CE14 的 `-1` 明确定义为「ロード画面」。
3. **已证实**：CE43 只负责把三行 `menu*_b/menu*_a` 图片画到槽 3/4/5，并按 `Sys20` 重画一行亮态。它在 `pc27` 执行 `172 BreakEvent`，其后的 `pc28-56` 鼠标悬停检测全部不可达；CE43 没有图片点击热区或图片到 `401` 分支的映射。
4. **数据已证实 / 原版单次探针已观察**：菜单位置不再移动指针、直接点击视觉第三行 `(100,510)`，仍执行了当前高亮的第 0 项并进入新游戏声明；进程未退出。CE43 在 `172` 之后没有可执行图片命中代码，探针与该事实相符；最合理的解释是原版第二次点击确认了 CE42 原生 `102` 的当前选项，但精确的原生命中规则仍需更多输入矩阵才能完全定义。
5. **已证实**：Map003 的 `pc22` 与 `pc26` 是两条独立的 `180[50]`，不是一条 100 帧。两条合计 100 个逻辑帧；中间 `pc24` 的 30 帧擦除是非阻塞的，不能把 100 帧直接解释为完整黑屏时长。
6. **部分验证**：`Game.exe` 静态导入、路径字符串和关键立即数层面未发现标题/新游戏专属补丁；证据只到 IAT/字符串/选定立即数 xref，不能据此声称“绝不存在任何计算型钩子”。

### 3.1 CE14 参数证据

CE14 的形参枚举与值页为：

```text
value_pages[0] = [0, 4294967295, 1, 2, 3, 4]
string_pages[0] = ["セーブ画面", "ロード画面", "アイテム画面", "技能画面", "装備画面", "システム画面"]
```

CE14 的关键槽位：

```text
pc4  111 [1,1600000,-1,2]   ; 参数 == -1
pc6  103 ["ロード画面"]
pc7  300 [0,2,1,1] "X┣[移]セーブ欄実行"
```

因此 `-1` 是 `ロード画面`，`0` 是 `セーブ画面`。`210 [500014,1,-1]` 中的 `1` 是 `param_status` 的数值参数个数，不是菜单编号。

### 3.2 “点击开始咯没有 HasSave 特判”

- CE42 的新游戏分支从 `pc114 401[2]` 到 `pc118 130` 之间只有注释、`180[12]` 与传送，没有任何条件读取存档存在性，也没有 `210/220/221`。
- `TitleMap.mps` 的 `Sys7` 初值逻辑只影响原生 `102` 的当前光标；它不改变任何 `401` 分支体。
- 当前 Godot 宿主 `GameSession.PickChoice` 确实有一段 `Phase == "title" && index == 1 && HasSave` 的快捷读档分支（`godot/core_cs/GameSession.cs:340-348`），但它是移植层为测试/宿主保留的兼容分支，不是 CE42 的数据行为；交互标题路径另走 `SelectTitleChoice`（同文件 `:358-362`），直接投递 VM 选项。
- 因而“开始咯是否被 HasSave 改写”在数据层的答案是：**不会被改写**。当前宿主代码和原版脚本的数据边界需要分开陈述。

### 5.1 50 帧的精确解释

- `pc22 180[50]`：50 个逻辑帧。按 60 Hz 为 **0.833333 秒**。
- `pc26 180[50]`：另一段 50 个逻辑帧，同样 **0.833333 秒**。
- 两段合计 **100 帧 = 1.666667 秒**；中间只插入立即执行的 `pc24`，没有第三条 50 帧等待。
- `pc9` 到 `pc28` 还有 `pc12 180[1]`，因此该区间的显式等待为 **101 帧 ≈ 1.683333 秒**；若把 `pc8` 的 1 帧也算进去，则为 **102 帧 = 1.700000 秒**。这是按 60 Hz 逻辑时钟的推导，不代表对零售窗口做了逐帧计时采样。
- `pc9` 的 30 帧淡入（0.5 秒）、`pc13` 的 20 帧淡出（0.333 秒）和 `pc24` 的 30 帧淡出（0.5 秒）都与 `180` 并行；因此“两段 50 帧”是脚本阻塞节奏，不是完整黑屏或淡出时长。

- 实际导入 9 个 DLL、168 个符号：`SHLWAPI.dll`、`PSAPI.dll`、`KERNEL32.dll`、`USER32.dll`、`GDI32.dll`、`SHELL32.dll`、`WININET.dll`、`CRYPT32.dll`、`ADVAPI32.dll`。

- 静态导入表没有 `GuruguruSMF4.dll`、MIDI API 或 DirectX。PE 中存在宽字符串 `GuruguruSMF4.dll`（文件偏移 `0x481e74`、`0x482508`、`0x48ad40`），并存在 `LoadLibraryW`（`0x40296F`）与 `GetProcAddress`（`0x435660`）动态加载调用点；因此 MIDI DLL 是运行期动态加载，不能只看静态导入表。
- `.rdata` 命中通用文件路径：
  - `BasicData/CommonEvent.dat`（文件偏移 `0x498EE4`）
  - `Save/SaveData`（`0x4993E4`）
  - `Game.ini`（`0x498F94`）
  - `Data/` 8 处，`.wolf` 1 处；`Data/`/`.wolf` 有代码立即数 xref（`0x401380` / `0x4013A0`）。
- 选定标题/新游戏 ID 的原始 32 位小端立即数 `500014`、`500042`、`500264`、`4131`、`9000004`、`9000020` 在 `.text` 的 push/mov/cmp 立即数 xref 中均为 0 命中；这只能说明没有直接写死这些常数，不能排除计算生成。
- TLS 目录存在，但 TLS callback 指针为 0；load config 目录存在，不等同于标题事件钩子。

## 7. 对当前复刻的直接影响

- **可靠的数据映射**：行 0 → Map003，行 1 → CE14(-1)，行 2 → 退出。
- **移植层重建**：当前 Rust/Godot 的图片行级热区、`Sys20` 高亮刷新、`choose_title_menu_row` 的显式行分派，是复刻层产物，不是 CE43 的可执行数据行为。
