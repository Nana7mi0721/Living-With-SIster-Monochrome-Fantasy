## 1. 结论

`docs/HANDOFF_M12.md` §5.4 第 2 项与 `docs/MAP_AUDIT.md` §9 第 4 项问的是：「事件格点击」和「图片悬停」两套判定如何交互。答案：

- **五个 confirm 页是空的页选择器**（ev11/14/18/21/22 各自的 confirm 页）。它们存在的唯一作用是：当 `v302 == 1` 时成为该事件的最高活动页，从而停掉事件原本的 parallel 页。没有任何命令，也不需要被点击。
- **第六个（ev24 page 6）是唯一的真实 confirm 处理页**，但它最后一个条件是 `self0 == 99`；扫描全部 550 个公共事件与 9 张地图的所有页，**没有任何脚本写过 magic `1_000_000`（事件自变量 0）**。`self0` 恒为 0，因此该页只在编辑器/调试器里可达，不是零售流程。
- 因此零售的点击**完全走 `124` 对图片的悬停/点击**，其命中框就是图片的绘制目标矩形（`Game::picture_hover`，已由 `m8_hover_anchor.rs` 覆盖）。事件格坐标（0..10, 33/35）在屏幕上压在整屏背景图层之下，不是 HUD 命中区。

## 2. 六个页的实测数据（SampleMapA.mps）

| 事件 | 页 | trigger | 条件 | 真实命令数 | 判定 |
| --- | --: | --- | --- | --: | --- |
| ev11 ■深夜UI判定 | 1 | 0 confirm | `v302 == 1` | 0（仅空指令） | 页选择器 |
| ev14 ■深夜UI処理 | 1 | 0 confirm | `v302 == 1` | 0 | 页选择器 |
| ev18 ■■処理さわる右 | 1 | 0 confirm | `v302 == 1` | 0 | 页选择器 |
| ev21 ■■処理さわる左 | 1 | 0 confirm | `v302 == 1` | 0 | 页选择器 |
| ev22 ■中央クリック処理 | 3 | 0 confirm | `v302 == 1` | 0 | 页选择器 |
| ev24 ■例外処理実行 | 6 | 0 confirm | `v60 == 4`、`v60 != 1`、`v124 >= 1`、`self0 == 99` | 251 | 调试专用，零售不可达 |

页优先级规则（`MapEvent::active_page_index`）从最高页往下找第一个条件全成立的页。测试用闭包提供变量：

- `v302 = 0` → ev11/14/18/21/22 的活动页是 **0（parallel）**；`v302 = 1` → 活动页变**空 confirm 页**（1/1/1/1/3），parallel 页因此停止。
- ev24 在 `v60=4, v124=1, self0=0` 时活动页是 **5（autorun 例外路径）**；只有 `self0=99` 才是 **6（confirm 页）**。

## 3. 命中的实际分布（SaveData01）

事件格中心像素（`tile * 16 + 8`）上，`124` 的悬停结果：

| 事件格 | 像素 | 悬停到的图片 |
| --- | --- | --- |
| ev18 (0,33) | (8,536) | −10、−7、−1（整屏背景层） |
| ev21 (2,33) | (40,536) | −10、−7、−1、**107**（`Picture/sub_button01.png`，x=20 y=505） |
| ev11 (3,35) | (56,568) | −10、−7、−1 |
| ev14 (4,35) | (72,568) | −10、−7、−1 |
| ev22 (7,35) | (120,568) | −10、−7、−1 |
| ev24 (10,35) | (168,568) | −10、−7、−1 |

也就是说：事件格并不对应按钮；玩家看到并点击的底部按钮是**图片 107 的矩形**。测试同时断言 (20,505) 在图片内、(19,505) 在图片外，确认命中框是绘制矩形而不是事件格。

## 4. 为什么不需要实现「事件格点击」

- WOLF 的 trigger 0 是**决定键**触发（页面不带图形，玩家看到的是图片）。端口 `MapRuntime::try_trigger` 已按 `ActionKey` 处理它，但零售流程从不依赖这些空页。
- 五个页的作用是「把 parallel 页关掉」，触发方式（键/点击）对结果没有影响；把鼠标点击映射到事件格反而会引入零售没有的行为。
- `Game::picture_hover` 的命中框是 `Picture::destination`（锚点、缩放、精灵格、效果都参与），与绘制一致；`124` 的 field 8 就是它。底部的 sub button 107、战斗按钮 3090/3200 等全部走这一条。

## 5. 边界

- 本次只审计 SampleMapA 的 6 个 confirm 页；`SampleMapB`/`Dungeon` 是 WOLF 示例图，不计零售（见 `M12_RETAIL_SCOPE.md`）。
- `self0 == 99` 的不可达结论基于「全部公共事件 + 全部 9 张地图的 121/122/124 目标扫描」。若未来发现引擎会在某条件下自动初始化该槽，需要重新评估；现有数据中没有任何写入。
- 命中测试依赖 SaveData01 的图片布局（零售固定数据）。缺零售存档时跳过。
