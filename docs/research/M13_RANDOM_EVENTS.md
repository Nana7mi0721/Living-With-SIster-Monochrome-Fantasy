## 2. 方法

1. 事件池分发定位：WolfTL dump JSON 每条命令的 index 字段 == 运行时实例 inst.pc。因此把某个池（如 CE277/CE278/CE279/CE280）入口的选择器 self 变量设为目标值，再把 inst.pc 设为分发的第一个 111 条件块（CE278 需跳过 @10 的 RNG，直接置 pc=11），即可确定进入目标事件块，无需依赖随机。
2. 条件型事件：用小状态注入（self 选择器或全局 var），并 pc 跳到已知分支注释的 index，断言渲染出预期台词且 warnings==0。
3. 死链排查：遍历全部 Program（event id 0..2000）的 op210/211（CommonEvent）与 op300（CallByName）调用目标，逐一解析；解析不到且非动态（非 storage magic / 非含反斜杠·cself·{ 的名字）者记为死链，逐条打印 CE@pc 与目标名。
4. 默认测试快（4 项）；全池扫描标记 #[ignore]，手动加 --ignored 运行。

关键标定：inst.pc 就是 dump 的 index 字段（不是列表位置、不是数组偏移）。实测 pc=某 index 时，第一条渲染的 Message 正是该 index 对应的台词（例：CE326 idx1323=「好好吃！！！」、idx1145=「感觉食欲爆发啊。干劲上来了。」、idx1378=「啊，要珍惜粮食呢。」、idx1412=「超级像鸡鸡诶！！」；CE301 idx1145=「留下来继续训练了！」）。
