## 0. 结论速览

- 真实战斗攻击命令此前“全部不可选”的精确断点在 CE152 pc89..pc95：技能行的「発動アイテム要する?[消費]」列（Data type0 col20）在本版数据里整列缺失（Data type0 field_count = 18，col20 越界），读操作不写目标变量、变量保持 0 → CE152 走 1600014 >= 0 分支 → 再去读「所持アイテム個数」（CData type7）第 0 行的数量 → 空背包 = 0 → 1600012 <= 0 成立 → 把该命令行写回“不可用”。
- 修复（数据前置条件，非伪造菜单行）：给背包种一行 CData type7（所持アイテム個数）row 0 col 0 = 1。此后所有真实攻击行（命令码 26/25/30/29）在万能ウィンドウ里 選択可能 = 1，可被确认。对照实验（只种队伍+命令槽、不种背包）仍全部不可选，因果关系成立。
- 边界（本测试钉住、未伪造）：
  1. 仅从 CE188 起，永远到不了 CE244：CE188（X◆戦闘処理）没有任何 210 CALL 500244；写 2000352/2000343 的 CE244 只被 CE239（pc201/302/414/555/614/746/865/943/1047/1124/795…）、CE241、CE242、CE243 调用。要结算必须进 CE239 战斗调用上下文。
  2. 命令确认后进入 CE157 味方欄 / CE158 敵欄 目标选择窗口，纯 OK 输入下目标未提交即返回，CE192 回到命令列表，2000349（経過ターン）不前进。
  3. 直接 start_event(239) 驱动会停在 pc13（需要活的地图/战斗演出上下文，诊断 “201 SetMoveRoute ... no map layer”），不能从冷存档推进到 CE244。
因此本任务以“真实攻击行变可选 + CE192/CE20/目标窗口到达”为最深诚实断言。
