## 4. How CE452 is driven (mechanism)

CE452 is one large dispatcher on its own self variable slot 10 (self10, magic
1_600_010 = self group 6 slot 10 = flat self-vars index 610).

- @pc 2: var619 (2000619) = self10 (1600010).
- Ten sequential 111 Condition blocks (pc 3, 654, 1145, 1559, 2183, 2912, 3835,
  4593, 5175, 5866). Each block is four conditions "self10 == 4k .. 4k+3"; the
  first match jumps to that EP body, no match falls through. **EP number == self10.**
- @pc 6087: self10 += 1 (compound kind 0x100 = current + value), then the event
  ends.

So **one invocation plays exactly one EP**. To play EP n the test starts CE452
and seeds self10 = n; var619 must then equal n and pc must reach EP n's marker.

## 7. Entry wiring after the M13 common-self fix (self10 now persists)

The single in-data caller is CE251 @pc 2498 = 210 CallCommonEvent, target 500452,
with **param_status = 0 => zero numeric arguments**, so it does NOT seed self10.

Before the M13 fix this meant an organic playthrough only ever replayed EP0: each
invocation of CE452 got a fresh all-zero self-vars bank, so self10 reset to 0 and
var619 never advanced (matching the all-zero retail saves). The M13 common-self
persistence fix (crates/wolf-vm/src/exec.rs + wolf-game part3 save/restore) makes a
common event's self variables persist across separate start_event invocations, so
self10 accumulates 0,1,2,… and var619 advances naturally without injecting self10.

Proof (test `dlc452_self10_persists_across_calls`, #[ignore] long):
repeated zero-arg start_event(452) in one game — at each entry self10 == number of
EPs already played (NOT 0), var619 == that number, and the trailing self10 += 1
carries it forward. Measured natural progression var619 = 0..=25 across EP0..EP25
(27 calls; self10_after = 1..=26). **At EP26 self10 stays 26**: that EP's body ends
the event before the self10 += 1 tail, because later EPs gate on additional DLC
state (e.g. self11) that a fresh game does not have. So a bare repeated zero-arg
call cannot reach EP36 on its own — this is a data-control-flow property, separate
from the self-vars reset bug the fix removes.

Every EP1-EP36 is still individually reachable (and measured in §5) by seeding
self10 = n, which is what a caller that actually varies self10 would do. Script
evidence: the dump's 452 dispatcher expects self10 to vary (ten blocks x four
values = 40 slots).

Note: CE452's final dispatch block (pc 5866) has case slots for self10 36..39, but
the dump defines EP bodies/markers only through EP36 (@5869); 37-39 have no EP
comment marker and are out of scope.
