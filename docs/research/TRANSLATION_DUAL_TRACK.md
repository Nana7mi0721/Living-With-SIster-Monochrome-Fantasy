# 中文双轨方案（官方校对轨 + 彼梦精翻轨）草案

> 2026-11-02 起草。背景：用户引入安卓彼梦精翻仓库（ArchiDreamZ/Living_With_Sister-Monochrome_Fantasy-Android-Chinese_localization，分支 Archi），语料已抽取到 work/translation/（见 [work/translation/REPORT.md](../../work/translation/REPORT.md)）。本文只给方案，未改源码。用户原话要点（m00888）：
> - 保留**两套中文**：一套**官方**（神乐/Kagura，需校对，官方也可能有误），一套**彼梦精翻**。
> - **文字贴图**：若安卓精翻仓库给的是压缩后图片、质量不如官方，则**贴图内名词采用官方中文**。
> - **台词**：使用**彼梦精翻**；但若台词里指向了某张文字贴图的文字，则**替换为官方的标准用词**（与贴图保持一致的术语）。
> - 规则暂定，欢迎更优方案。

## 0. 结论速览
1. 能落地。核心不是“选哪套中文”，而是**把“图像像素质量”和“图中文字内容”解耦**，再用**术语规范表（canonical glossary）**把两条中文轨统一到同一套术语上。
2. 默认输出：**台词取彼梦精翻**（更自然），**UI 贴图取清晰的那版图源**（多为官方），**任何“台词引用了贴图标签”的词强制回填为 canonical（默认=官方）**。
3. 官方轨保留为**校对轨**：登记官方错译/笔误并给出 corrected_zh，它同时充当 canonical 术语的权威来源（因为贴图多半是官方图）。
4. 已用 CE280 做过一次 1:1 对齐验证（附录 A.1），并顺带证实官方文本确有笔误（“再买一点”→“慢一点”）。

## 1. 关键概念纠偏 —— 图像质量 ≠ 文字内容
用户把“贴图质量”和“贴图文字”绑在一起；实际拆开后方案更简单也更稳：

- **图源（像素）**：分辨率/位深/有损压缩程度。只决定“用哪张图更清晰”。
- **图内文字（标签）**：这张图上写的词（如“行动力”“公会战力”“深山位”）。只有当两个版本的图**文字内容本身不同**时，才需要选择用哪套文字。

多数情况下，安卓精翻图若只是**被压缩**，文字内容并未改变，那么“用官方高清图”并不改变标签，台词按官方术语回填即可。真正需要人工裁决的，只是**极少数两版图文字不一致**的贴图。

> 因此规则可改写为更可执行的形式：**图源选清晰版；图内标签以“实际采用的那张图上的字”为准，登记进术语表；台词引用该标签时按术语表重写。** 这样“台词指向贴图文字就用官方标准”就由术语表机械保证，不必逐句肉眼比对。

## 2. 数据模型（每条翻译单元 Translation Unit, TU）
```
TU = {
  wolf_ref:    event/page/pc        # 权威坐标，与移植端一一对应
  mv_ref:      file/event/page/idx  # 对齐到的彼梦语料坐标（可为空）
  official_zh: string               # 神乐官方中文（来自 .wolf 原始 message）
  bimeng_zh:   string               # 彼梦精翻（来自 MV 语料，经对齐）
  final_zh:    string               # 运行时采用
  source:      bimeng|official|mixed
  terms:       [term_id...]          # 本句引用到的术语/贴图标签
  align:       {method, score}       # 对齐证据（时序/相似度）
}
```

## 3. 术语规范层 work/translation/glossary_canonical.tsv
列：term_id, ja, official_zh, bimeng_zh, canonical_zh, on_image, image_asset, note
- canonical_zh 默认 = official_zh；官方明显错时在 note/校对轨覆盖。
- **术语归一化重写（normalize）**：对每条 final_zh，若句中出现某术语且 on_image=true，把彼梦用词替换为 canonical_zh。
  - 例：贴图写官方“深山位”、彼梦台词写“深山”，则台词统一成“深山位”。
  - 例：数值/系统词“行动力/性欲/体力/精力/公会战力/好感度/信赖”等，全部以 canonical 为准。
- 非贴图术语（纯对白口语词）**不强制**，保留彼梦文风。

## 4. 贴图源选择 work/translation/image_plan.tsv
列：asset_id, wolf_path, bimeng_path, pick(官方|彼梦), metric, label_terms, note
- 质量评分：分辨率、位深/是否调色板、有损压缩痕迹（JPEG 量化/块效应）、可选 SSIM(彼梦图 vs 官方图)。
- 规则：彼梦图质量 < 官方 → pick=官方（默认），否则可 pick=彼梦。
- label_terms 记录该图上的标签术语，回填 glossary_canonical。
- **与台词联动**：image_plan 决定“这张图显示哪个词”，glossary 以所选图为准，台词再按 glossary 重写 → 闭环。

## 5. 官方校对轨 work/translation/official_review.tsv
列：wolf_ref, official_zh, issue_type, corrected_zh, evidence
- 登记已知/新发现的官方错误；即使最终台词用彼梦，官方轨仍用于：① 提供 canonical 术语；② 万一某句只能用官方中文时保证它是对的。
- 首批示例（附录 A.1）：CE280 pc36 官方“真是的，哥哥你吃东西得再买一点才行啦。”→ 笔误，应为“…再**慢**一点…”（“买”→“慢”）。证据：彼梦 CE280@48“……吃东西的时候要**细嚼慢咽**哦。”（第三套独立译文同义）。
- 待收：HANDOFF_M12 记录的 D46“体力 35 漏负号”、D11“胜/败文案重复”等。

## 6. 流水线（脚本放 work/translation/，不改源码）
1. **align**：剧情时序单调对齐（LCS/DP + 翻译相似度，\\N名字/地名做锚点），产出 aligned.tsv。CE280 已证可 1:1（附录 A.1）。
2. **select**：默认 final=bimeng_zh；对齐缺失/低分 → 回退 official_zh。
3. **normalize**：按 glossary_canonical 对 final 做术语重写（仅 on_image 强制）。
4. **emit**：按事件产出 final_zh 文本表 + image_plan.tsv，供移植端注入。
5. **verify**：术语一致性（台词里的贴图术语 = 图标签）、未译/日文残留、“图源-文字”配对检查。

## 7. 运行时注入
- 移植端 message 指令读 final_zh；贴图按 image_plan 选资源。
- 注意（REPORT §7）：T++/MV 条件脚本里的字符串（如 $gameVariables.value(602)==='コミュニケーション'）不能直接翻译，需按 ==='日文' 精确注入，否则按键/多周目继承失效 → 术语表变量 ID 必须与脚本常量一致。

## 8. 备选策略比较（回答“能否找到更好方案”）
| 策略 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 彼梦默认 + 术语重写（本文默认） | final=彼梦，贴图术语强制 canonical | 文风最好、术语一致由表保证 | 依赖对齐质量；对齐缺失句回退官方 |
| B. 官方骨架 + 彼梦 delta | final=官方（术语/语义基准），仅当彼梦与官方语义一致且无术语冲突时用彼梦润色 | 天然术语一致、与官方贴图完全对齐 | 彼梦“精翻”文风只在无冲突句生效 |
| C. 术语表驱动（A/B 的底层） | 统一 canonical 术语表，任何来源都先归一化再输出 | 与来源解耦、可增量 | 需要维护术语表 |

> 建议：**以 C 为底座，A 为默认输出，B 作为“高保真/贴图密集”场景开关**。既保留彼梦文风，又保证 UI/贴图术语一致，可随时切“官方优先”。
