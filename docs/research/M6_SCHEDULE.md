### 3.4 真正可选的非战斗路径：换一行菜单

- day4 菜单有 5 行，m6 固定点第 1 行（图片命中点在 x=512,y=230 的第 1 行按钮，pic1200/1201）。若能点中内部 id ≤6 的一行（CE252 鍛錬，确定无战斗），当天就会正常返回→晚间→就寝→day5。

### 3.5 精确的缺失环节

- 缺的不是日期链，也不是 CE244 结算/CE326/CE329：这些都齐。**缺的是 CE239 战斗线里「等玩家命令（2000350=1）」这一态的落地——即由引擎 condvar 启动的 CE242/CE192 需要能基于 CData type0 的 8 个命令槽渲染出可选命令菜单。** 没有它，CE242 永远产不出可交互命令，CE239 永不返回，CE253 永不回流，day4 就停在 15:00。

## 4. Q3：CData type0「主人公ステータス」命令槽 47..54/56 的初始化缺口

### 4.1 列定义

- docs/PARTY_DB.md:355：CData arg0=0（主人公ステータス）运行列 **47..56 = [コマンド1..8]**（另 57/58 经验值、59 AI、60 必要经验增量）。
- docs/PARTY_DB.md:331-364 §4.1/§4.2：.dat 类型 0 只有 51 个字段，运行时列用 0..60 且**不与 .dat 字段序对齐**（运行列 4=レベル vs .dat fi4=顔画像）；列号随编辑器版本漂移，不能用 column<field_count 来校验。

### 4.2 CE143/CE150/CE151 链：只读源槽、只写战斗临时库

- **CE143（X[戦]主人公DB→戦闘DBコピー，205 cmds）**：index 51-58 用 `250 [type0, row=1600001, col=47..54, flags=331776, dst=1600070..1600077]` **读**主人公ステータス这 8 个命令槽（flags 0x51000 bit12=1 = DB→var 读）；string 标签正是「[コマンド1]…[コマンド8]」。随后 index 62+ 把值**写入 type10 戦闘一時ステータス**临时库（bit12=0 写）。**它只把源槽拷出去，从不写回 type0 的 47..54。**
- CE143 的调用者：**CE190（キャラ配置）pc17**、CE142 pc18、CE5 pc68（均为 300 名字调用）。
- **CE151（X[戦]戦闘コマンド設定，66 cmds）**：把 type10 的 cols 27..34 [コマンド1..8] 从 self1600002 写入（bit12=0）；index 29/43/58 先调 CE150 找空位。调用者：CE143 pc231/236/241/244。
- **CE150（X[戦]戦闘コマンド取得，32 cmds）**：读 type10 cols 27..34 [コマンド1..8] → self1600010（bit12=1）。调用者：CE151、CE152。
- **结论**：CE143/CE150/CE151 整条链只在 type10 战斗临时库上工作，其源头是 type0 的 47..54，而 CE143 对这些源槽**只读不写**。三者都不能凭空造出合法命令。

### 4.3 谁写 CData#0 的 47..56，以及为什么新游戏路径没人写

- **CE26（戦闘コマンド初期設定）**：index 0 令 1600030=0，然后循环槽 0..7 各调一次 CE78（戦闘コマンド取得，args=[0,16777218,1600000,slot,1600020]），把每条默认命令写进 CData#0（写 cols 49..56）。**但 CE26 的调用者数 = 0**（全库扫 210 字面量 500026 与 300 名字调用，均 0）。
- **CE77（戦闘コマンド設定，菜单用）**：写 cols 49..56。唯一调用者是 **CE13 pc1**，而 **CE13 的调用者数 = 0**。
- **CE78（戦闘コマンド取得）**：写 cols 49..56 ← self1600020；调用点共 9 个，其中 8 个来自 CE26 的槽 0..7（另 1 个在菜单侧）。
- 旁支写者：CE71 パラメータ取得 pc25 写 col53；CE90 キャラクター描画 pc165-166 写 cols48-49。
- **关键**：新游戏路径里**没有任何 common/map 事件调用 CE26/CE77/CE13** 来初始化这 8 个槽。它们的值来自随包 **Save/System.sav** 模板（Game::new 加载 root/Save/System.sav）——即「新游戏」的初始状态就是随包存档模板，而不是运行时用静态 DataBase 算出来的。静态 DataBase 里也**没有**每角色的命令表。

### 4.4 直接 start_event(188) 实测：产不出命令

- `./target/debug/wolf-cli --root work/full run --event 188 --frames 600`：instructions 147245、peak coroutines 3、messages 0、choices 0、pictures 4843、database ops 10790、warnings 0。
- `--frames 4000`：instructions 980245、peak coroutines 3、messages 0、choices 0、pictures 32043、database ops 71990、warnings 0。
