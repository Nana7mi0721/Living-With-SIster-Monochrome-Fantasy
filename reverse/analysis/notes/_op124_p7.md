Windows 控制台是 GBK，脚本首行都做了
`sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8', errors='replace')`。

## 附录 B　与其它文档的关系

- `docs/FORMAT_SPEC.md` §3：指令流的字节级编码（param_count / branch_depth / 字符串表）。
  本文只讲 124 的**参数语义**，不重复字节布局。
- `docs/OPCODE_SPEC.md`：全部 opcode 的总表。本文是其 124 条目的**实测扩充**。
  注意该文件 §5.19 说 150 的图片号取 `(uint8_t)int_args[1]`，对本作**不成立**
  （图片号到 5 位数），以本文 §1.2 为准。该文件由 lead 维护，我未修改。
- `crates/wolf-vm/src/exec.rs`：121 / 124 的实现位置（`binary_op` / `compound` 已存在，
  124 待接本文 §6 的伪码）。
- `crates/wolf-game/src/picture.rs` 的 `mod field`：150 的槽位常量表。本文 §6 引用的
  `FLAG / WINDOW_W / WINDOW_H / RESERVED / OPACITY / X / Y / SCALE / BLEND / EXTRAS` 即出自此处
  （150 的 `PictureCmd::args` 对应指令参数 `a[2..]`，a[0] = flag、a[1] = 图片番号）。
