### 1.3 官方手册逐条原文（已验证，curl 抓取）

    + フラッシュ … 指定した赤・緑・青の値をピクチャの「カラー」に加算して1回だけフラッシュします。±200までの値に対応。
    + カラー補正 … 指定した赤・緑・青の値だけピクチャの「カラー」に加算します。±200までの値に対応。
    + 描画座標シフト[最終値] … 指定したX、Y値だけ、ピクチャの描画座標をずらします。単純に最終値をシフトさせるものです。
    + シェイク … 指定したX、Yの移動分で、指定回数だけピクチャを揺らします。「処理時間」フレームが短いほど、高速に振動します。10万回以上にすると無限になります。
    + ズーム … 指定したX、Y座標を中心に、指定した拡大率でピクチャをズームします。
    + 点滅A[明滅] … 指定したRGB分（最大±200）の差だけ、指定フレームでカラー変更による明滅（変化前、変化後、と交互に変化する）を繰り返します。「RGB値全てを０に設定する」か、または「フレーム数を０にする」と、点滅は停止します。
    + 点滅B[自動ﾌﾗｯｼｭ] … 指定したRGB（最大±200）の±分だけ、指定フレームでカラー変更によるフラッシュ（ウェイトせずに変化してから元に戻っていく）を繰り返します。…（停止条件同文）
    + 自動拡大縮小[％] … 指定した縦・横の拡大率の±値分だけ、指定フレームでピクチャを拡大縮小します。1回の拡縮後、休フレームだけ一時停止します。「鼓動」をイメージすると分かりやすいと思います。
    + 自動ﾊﾟﾀｰﾝ切替[1回] … 指定した開始パターン～終了パターンまで、パターン番号を1ずつ指定フレーム間隔で切り替えます。一回分のパターン切り替えが終わったら、ピクチャ側で設定された元のパターン番号に戻ります。
    + 自動ﾊﾟﾀｰﾝ切替[ループ] … 指定した開始パターン～終了パターンまで、パターン番号を1ずつ指定フレーム間隔で切り替えます。終了パターンまで切り替わったら、また開始パターンに戻ってループします。
    + 自動ﾊﾟﾀｰﾝ切替[往復] … 指定した開始パターン～終了パターンまで、パターン番号を1ずつ指定フレーム間隔で切り替えます。終了パターンまで切り替わると、開始パターンまで1ずつ戻り、ループします。

另外三条全局约束（同页）：

1. **效果与 150 完全独立**：「ピクチャに対するエフェクトは、「ピクチャ」処理で指定した内容とは独立して処理されます」；「座標シフトを行うと、ピクチャ処理で指定したX、Y座標＋座標シフト分のX、Y座標に描画され続けます。これは座標シフト分のX、Y値を0に戻すか、ピクチャを消去するまで有効です」。
2. **效果不会被「変数操作＋」读到**：「全ての「エフェクト」コマンドは、「変数操作＋」で取得される値には影響を与えません」—— 只有 124 的 0x4000（带补正）才把 shift 叠上去。
3. **カラー被夹在 0..200**：「「フラッシュ」や「色調の加算」は、「ピクチャ」処理時のカラー「0～200」の範囲を超えて色調が変わることはありません」⇒ 无论怎么叠加，有效颜色的百分率 p ∈ [0, 200]，100 = 原色。

## 2. 逐类型语义

### 2.1 type 3 —— シェイク（已验证）

- 250 条，是本作第二多的类型。処理時間 **15 帧占 163 条**（= 一次往返的帧数），另有 2/4/30/50 等。
- 参数：`v1 = シェイクX`、`v2 = シェイクY`（位移幅度，像素）、`v3 = 回数`。
- 实测 (X,Y) 组合：`(0,2)`×132、`(0,1)`×42、`(6,0)`×14、`(8,0)`×12、`(0,0)`×11、`(7,0)`×6、`(2,0)`×4、`(0,8)`×4 ⇒ **绝大多数是「竖直方向 1~2 px 的轻微抖动」**（立絵/演出时的「颤抖」）。
- 回数分布：`99999`×124（正好卡在「10万回以上 = 无限」之下）、`999`×52、`3`×36、`9999`×8、`8`×10、`0`×7、`999999`×2（= 真的无限）。
- 典型用法：
  - ev241「┣ターン開始処理」pc219..222 的**阶梯式震动**：`[48,2,3010,3010,6,0,3]` → `[48,3,3020,3020,8,0,3]` → `[48,4,3030,3030,8,0,3]` → `[48,4,3040,3040,7,0,3]`，然后 `180[20]` 等待 —— 每次 (X=6/8/8/7, Y=0, 回数=3)，処理時間 2/3/4/4 帧，即**越摇越快、越摇越大**的受击表现。
  - ev452（41 条）与 SampleMapA:ev15（36 条）是「持续微抖」的常客（`(0,2,99999)` 一族）。
- **实现模型**（高置信）：持续时间 = `回数 × 処理時間` 帧；每 `処理時間` 帧把绘制偏移翻转一次符号（+X/+Y → −X/−Y），或在该区间内取正弦；`回数 ≥ 100000` ⇒ 永不结束（本作 2 条 999999）。`v1=v2=0` 的 11 条等价于「空转计时器」，无害。
- **未确认**：抖动是「严格交替符号」还是「每帧在 [−X, X] 内随机」（原版可能用随机 ± 以求自然）；两者的可见差异很小，建议先用交替符号，视觉不对再改随机。

### 2.2 type 1 —— カラー補正（已验证；初版误标为「点滅复位/停止」）

- 61 条（公共事件 13 + SampleMapA:ev8 一处 48 条）。
- 参数：`v1..v3 = 赤/緑/青 的加算量`，±200。**処理時間 不参与语义**（§0.2：该 type 的摘要格式串一个 %s 都没有）；本作 dur 值是 0 或 1 的噪声。
- 语义（官方）：「指定した赤・緑・青の値だけピクチャの「カラー」に加算します」⇒ 给该图的カラー加一个**持续存在的加算项**，直到图片被消除或被再次指令覆盖。
- **关键用法（证明它必须实现成「设置」而不是「累加」）**：SampleMapA:ev8 的悬停高亮惯用法

      pc39  290 [16, 1, 3200, 3200, 25, 25, 25]   ← 被选中的选项：カラー +25
      pc40  290 [16, 1, 3201, 3201,  0,  0,  0]   ← 上一个被选中的：复位
      pc41  150 [16842753, …, 0, 0, 0, 1, 64, …]
      切到下一项时反过来再发一对（pc95/96 同形）

  ⇒ 如果引擎把 RGB **累加**到某个累加器上，(0,0,0) 就什么都清不掉，悬停几次后光标会越来越亮 —— 而全库**没有任何一条 `全エフェクト解除`（type ≥ 11 一条都没有，见 §0.1）**可用于补救。所以引擎的真实行为是：**把该图的「カラー補正项」赋成指定值（后写覆盖）**，渲染时再把这个项加到基色上。手册说的「加算」指的是「渲染时加到基色」，不是「累加到上一次的补正」。
- 其他用法：ev85 pc510 `(-100,-100,-100)` 配注释「全カーソルの色を消去」（范围 self21～self26，见 §0.4）⇒ 全部压成黑色；ev178 用 `(80,-30,-30)` / `(-30,-30,80)` / `(-30,80,-30)` / `(40,40,-30)` 给光标染红/蓝/绿/橙。
- **实现要点**：`pic.color_corr: [i32;3]`（默认 0），type 1 直接赋值；渲染时 `p = clamp(100 + corr, 0, 200)`。

### 2.3 type 2 —— 描画座標シフト[最終値]（已验证）

- 146 条，処理時間 124 条为 **0**（= 立即取最终值），另有 3 / 5 / 3000。
- `v1/v2 = シフトX / シフトY`，几乎都是自身変数引用：`(self11,self12,0)`×15、`(self70,self71,0)`×12、`(self72,self73,0)`×10、`(self51,self52,0)`×9 —— **成对的 self 变量 = X / Y**。`v3` 恒 0（未用）。
- 典型上下文 ev85 pc230：先 `121 [1600012, 1600089, 2, 12544]` 算坐标，紧接 `290 [32, 0, self21, self21, self46, self12, 0]`，然后 `150` 画。
- 语义（官方）：把绘制坐标整体平移，**永久保持**，直到再发一次 `(0,0)` 或图片被消除。与 124 的 `0x4400`（无补正）↔ `0x4000`（带补正）呼应：带补正读 X 会比基值多出 shift。
- 本作有 8 条 `(0,10,50)`：X=0、Y=10 的固定下移（用在 SampleMapA_1:ev5/ev8 的 800/801 与 3610/3611 成对图上）。
- **未确认**：两条 `処理時間=3000` 的样本，是否意味着「3000 帧内线性滑到目标」—— 官方说「単純に最終値をシフトさせる」，倾向仍然是即时，dur 只是编辑器遗留字段。

### 2.4 type 4 —— ズーム（已验证；初版误标为「图片切换 tween」）

- 49 条，処理時間 **恒 5 帧**。
- 参数：`v1 = 中心X`（**49/49 恒为 512** = 1024 屏宽一半）、`v2 = 中心Y`（200/250/300/350/400/450）、`v3 = 拡大率 %`（100 ×32、105 ×17）。
- 目标图片：1200/1201、1202/1203、1204/1205、1206/1207、1208/1209、1210/1211、1212/1213 —— **7 对「按钮底图 + 按钮文字」**，`d = arg3 − arg2` 有 43 条恰为 1（§0.4 的范围证据）。
- 用法：ev245「■夜コマンドメニュー」pc233 `[64, 5, 1202, 1203, 512, 300, 100]`、pc234 `[64, 5, 1200, 1201, 512, 250, 105]` —— 夜晚菜单里某个按钮「弹一下」（105% 再回 100%）。
- 语义（官方）：以 (中心X, 中心Y) 为中心按指定百分比缩放该图（组），`処理時間` 帧内到达；结束方式是**同中心再发一次拡大率 100**。
- **实现要点**：这是「围绕任意中心点的缩放」，`PictureState` 需要 `zoom_center` + `zoom_scale`，绘制时对包围盒做 `dst = center + (src − center) × scale`。

### 2.5 type 0 —— フラッシュ（已验证）

- 9 条，処理時間 **恒 25 帧**，picA == picB 9/9，图片号全为 self21（当前窗口/立绘）。
- 三元组只有四种：`(200,-100,-100)`×3、`(-100,200,-100)`×3、`(80,80,80)`×2、`(-100,-100,200)`×1 ⇒ **只抬一个通道**或**三通道一起抬**。
- 用法：ev90「X[移]キャラクター欄描画」pc508/523/538、ev178「X[戦]味方欄_単体描画」pc514/564/579、ev179。都是画完角色图立刻打一发。
- 语义（官方）：「指定した赤・緑・青の値をピクチャの「カラー」に加算して1回だけフラッシュ」⇒ 一次性把カラー推到 基色+Δ，然后在 `処理時間` 帧内回落到基色。
- **未确认**：`-100` 是「该通道不抬」的哨兵，还是「压暗 100」（因为 (200,-100,-100) 只留红通道亮 ⇒ 更像是**绝对值**：把 RGB 设成 200/−100/−100 再回落；负值在 0..200 域里会被夹到 0）⇒ 实现建议：`target = clamp(100 + Δ)`，回落用线性。

### 2.6 type 5 —— 点滅A[明滅]（已验证；初版误标为点滅B）

- 94 条。処理時間：**0 × 54**（= 停止）、50 × 16、15 × 9、25 × 6、30 × 4、20 × 1，另有 4 条自身変数。
- 三元组几乎总是三通道相等：`(100,100,100)`×36、（回到中性）、`(-50,-50,-50)`×29（本文主角）、`(0,0,0)`×19（= 官方停止条件）、`(-100,-100,-100)`×4、`(20,20,20)`×2。
- 语义（官方）：「指定したRGB分（最大±200）の差だけ、指定フレームでカラー変更による明滅（変化前、変化後、と交互に変化する）を繰り返します」⇒ **p 在 100 与 100+Δ 之间按 処理時間 帧往返（三角波）**，`処理時間 ≤ 0` 或 Δ = 0 停止。
- 典型「先关后开」成对写法：ev85 pc503/511 `[80,0,self21,self26,0,0,0]`（停）→ pc518 `[80,15,self21,self21,100,100,100]`（15 帧淡回中性）；ev234 pc663 `[80,50,10002,10002,-50,-50,-50]`；**TitleMap.mps:ev2 pc91 `[80,30,12001,12001,-50,-50,-50]`（标题横幅）**。
- type 6（点滅B）本作 0 条，**不要**为了「凑齐手册条目」去把 type 5 当 B 实现（那是初版 §4.3 的误判，修正见 §4.3）。

### 2.7 type 7 —— 自動拡大縮小[％]（已验证；初版未确认）

- 25 条。処理時間（= 拡縮時間，单程帧数）：10 × 8、20 × 6、15 × 5、0 × 5、self64 × 1。
- 参数：`v1 = 横％±`、`v2 = 縦％±`、`v3 = 休フレーム`。
- **决定性证据**：`v1 == v2` 在 **25/25** 条成立（因为「鼓動」是等比缩放），且编辑器摘要串有 **四个 %s**（`横%s％/縦%s％/ 休%sﾌﾚｰﾑ  拡縮時間[%s]ﾌﾚｰﾑ`）= 3 个参数 + 1 个処理時間，与实测字段一一对应。
- 实测组合：`(8,8,60)`×3、`(12,12,40)`×2、`(10,10,40)`×2、`(6,6,80)`×2、`(5,5,80)`×2、`(50,50,0)`、`(10,10,10)` 等 ⇒ 幅度 5~50%，休息 0~80 帧。
- 语义（官方）：「指定した縦・横の拡大率の±値分だけ、指定フレームでピクチャを拡大縮小します。1回の拡縮後、休フレームだけ一時停止します」⇒ 一个周期 = `拡縮時間`（→ +p%）+ `拡縮時間`（→ 0%）+ `休フレーム`（静止），无限重复。
- 用法：ev339（18 条，图片 6100 = 立絵）、ev270（6 条）、ev326（1 条）。
- **实现要点**：`scale = base × (1 + amp × tri(t))`，`tri` 为 0→1→0 的三角波；`休フレーム` 期间 scale 回 base。

### 2.8 type 8 / 9 / 10 —— 自動パターン切替[1回 / ループ / 往復]（已验证；初版未确认）

- 条数 51 / 104 / 21。参数：`v1 = 始パターン`、`v2 = 終パターン`、**`v3` 引擎不用**（§0.2）。`処理時間 = 間隔`（每格帧数，0 = 停止）。
- 语义（官方逐条）：把图片的**パターン番号**从 始パターン 起，每 `間隔` 帧 +1，直到 終パターン；三种收尾方式：
  - **1回**（type 8）：跑完一轮后**回到 150 里设定的原始パターン番号**；
  - **ループ**（type 9）：回到 始パターン 继续；
  - **往復**（type 10）：从 終パターン 逐格退回 始パターン，再重复。
- 实测佐证这个「帧动画驱动」的语义：
  - type 8 全在战斗侧：图片 5000（= `BattleEffect/[Attack]Slash01_panop.png`，28 条）、500/501、81；`v2`（終パタ）5~30 正是斩击序列的帧数；`処理時間` 2~4 帧 ⇒ 斩击动画高速播放。ev239 pc765 `[128,3,5000,5000,1,5,50]` 紧跟 `150[3150080, 5000, …]` 然后 `180[15]`。
  - type 9（ループ）图片 10000（65 条）/10100，`(始,終) = (1,2)` 占 72 条，`間隔 30` 帧 ⇒ 两帧循环呼吸/闪烁（约 0.5 s 换一帧）。
  - type 10（往復）图片 14/1000/1015/2103，`v1 ∈ {1,2}`、`間隔 0/10/15/20/30`。
- **实现要点**：这三个 type 不改颜色、不改坐标，只改 **`pic.pattern`**（150 的 パターン番号）。所以 renderer 必须把「当前显示的パターン」从 150 的静态值里分离出来，效果层驱动它；`1回` 结束时把 pattern 复位成 150 的值。
