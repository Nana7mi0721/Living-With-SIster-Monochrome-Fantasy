
## 5. 队伍槽 → 状态行（核心章节）

### 5.1 CDataBase 类型 6 = パーティー情報 **【已验证】**

| 项 | 值 |
|---|---|
| 文件类型下标 | 6 |
| property 列表 | [1000, 1001, 1002, 1003, 1004, 1005, 1006]（全是数值） |
| 字段数 | 7 |
| 行数 | **1**（只有 row 0） |
| 字段名（.project） | fi0 持有金额（钱）、fi1 メンバー1 … fi6 メンバー6 |
| field_type | [0, 2, 2, 2, 2, 2, 2]（fi0 数值，fi1..6 是**外键**引用主人公ステータス的行 id） |
| 行名（.project data_name） | メイン設定 |
| .dat row 0 实测值 | **[0, 12, -1, -1, -1, -1, -1]** |

解读：

- col 0 = 0 ⇒ 持有金额 = 0（初始）
- col 1 = 12 ⇒ **队伍槽 0（第一个成员）= 主人公ステータス 的第 12 行**
- col 2..6 = -1 ⇒ 槽 1..5 空

**-1 就是"空槽"的哨兵**，不是 row -1 的元查询语义（那个要求整个指令的 row 字段 == -1、且在读路径上）。两者不要混。

## 6. "row 100" 结案

### 6.1 现象

早期实现里大量 CData 读取的 row 是 **100**，而 CData#0 只有 17 行 ⇒ 全部 unanswered，状态面板画不出来。

### 6.2 根因链 **【已验证】**（Lead 定位，本文用字节复核）

1. CE98 pc26 按名字调 CE105，返回值落到 SV14；
2. CE105 用 **arg0 = 3** + 标签 パーティー情報 + col 1 + 标签 メンバー1；
3. 旧实现**先按整数**寻址：(CDataBase, 类型 **3**, row 0, col 1)；
4. 而 CDataBase 文件类型 **3** 是 **属性耐性**（100 个字段，40 行，row 0 全是 100）：

   ```
   CData#3 row0 ints[:6] = [100, 100, 100, 100, 100, 100]
   ```

   于是 (3, 0, 1) = **100**；
5. CE90 拿到 表示主人公ID = 100，之后所有 [0, 100, col] 的读都越界 ⇒ 全部 unanswered。

### 6.3 正确答案是 12

```
CData#6 row0 = [0, 12, -1, -1, -1, -1, -1]
                 钱  ↑ col1 = メンバー1 = 12
```

⇒ (CDataBase, 6, 0, 1) = 12 = 主人公ステータス 的玩家行。

**100 从来不是"运行时的第 100 行"，它是另一张表 row 0 col 1 的普通数值。** 两个数字差 88，但各自在表里都是合法格子 —— 这就是为什么这个 bug 不会当场崩，只会让画面全空。

### 6.4 真正的 100 是**参数号**：100 = "只重算"

**【已验证】** 这是全库唯一语义合法的 100。

CE70 X[移]パラメータ増減（686 条指令，形参 ['主人公データID', '対象パラメータ', '増減値', 'メッセージ有り?']）：

```
pc6   111 a=[1, 1600001, 100, 5]      if 対象パラメータ >= 100
pc8   注释：再計算　以外で
pc9   111 a=[1, 1600002, 0, 2]
pc11  注释：もし増減が0なら何もしない
…
pc665 111 a=[1, 1600001, 100, 2]      if 対象パラメータ < 100
pc667 注释：一時値再計算
pc668-670 300 调 X[移]一時ステ計算<初期化 / 装備補正 / 状態補正>
```

- 比较对象是 **1600001 = 第 2 个形参（対象パラメータ）**，不是第 1 个（主人公データID）。
- 全库 7 处把 100 当参数号传给参数库：CE7 pc3、CE9 pc38/pc64、CE10 pc9、CE11 pc14、CE12 pc14、CE200 pc81。例如 300 a=[0, 4, 1600000, 100, 0, 0] = 调用 パラメータ増減(角色 = SV0, 参数 = 100, 增减 = 0)。
- 语义：**参数号 0..99 = 真实列号；>= 100 = "不改值，只重算派生值"**。

CE71 X[移]パラメータ取得 给出的参数号 → (容器, 列) 映射（返回值放 SV99）：

| パラメータ | 目标 |
|---|---|
| 22, 23 | CData#0 col 5（HP） |
| 10, 11 | CData#0 col 4（レベル） |
| 20, 21 | CData#0 col 53（現Lvの取得経験値） |
| 30, 31, 32 | CData 类型 21（= ×主人公一時DB，运行 id 21）col 2（攻撃力） |
| 33, 34 | 类型 21 col 4 / col 5（精神攻撃 / 精神防御） |
| — | 防御力 = 类型 21 col 3；敏捷性 = 类型 21 col 6 |

### 6.5 全库没有字面 100 的行/列 **【已验证】**

2,592 个 250 站点里，arg1 == 100 或 arg2 == 100 的站点数 **= 0**。

另有 121 处 121 SetVariable 把常数 100 写进自我变量（图 id、坐标、计数器等）——那是**运行时的变量值**，静态追不到；从 CE105 / CE79 / CE5 的语义看，合法行号只可能是 0..16。

### 6.6 结论与防重犯

| 错误做法 | 后果 |
|---|---|
| 先按整数寻址，找不到再试标签 | 命中另一张表同址格子，静默返回错值（100 vs 12） |
| 用 arg0 直接做 .dat 数组下标 | 类型 3 ⇄ 6、5 ⇄ 8、6 ⇄ 9、17 ⇄ 18 ⇄ 19 全部错位 |
| 用 arg2 直接做字段下标 | 类型 0 的 60 个运行列里有 9 个超出 51 个字段 |

正确做法是 **R2：标签优先**。

### 7.2 row < -1 ⇒ 复位哨兵（18 处：17 写 + 1 读）**【已实测】**

17 处**写**的 flags 全是 0x10000（bit12 = 0），语义是"清空/复位这个工作表"：

| 站点 | 地址 | 目标表 |
|---|---|---|
| CE82 pc4 | (CData, 16, -2, 47) | × お店一時処理用 |
| CE86 pc9 / CE110 pc11 / CE111 pc11 / CE112 pc12 / CE152 pc6 / CE153 pc11 / CE154 pc11 | (CData, 19, -2, 0) | 万能ウィンドウ一時DB |
| CE157 pc28 | (CData, 14, -2, 6) | ×┣ コマンド処理リスト |
| CE188 pc195 | (CData, 18, -2, 11) | ×┗ お宝リスト（运行 id 18 → 类型 15） |
| CE189 pc16..pc21 | (CData, 10..17, -2, 5) | 战斗 DB 复制链（7 连发） |
| CE191 pc30 | (CData, 22, -2, 0) | 万能ウィンドウ一時DB |

唯一的**读**：CE270 pc34 (Data, 21, -3, -3) flags 0x11200（解析为 26 メッセージウィンドウ種類）。

实现规则：

- 写 + row < -1 ⇒ **不改任何格子**（它同时带 -1 作为 arg4 源值，但目标是整表清空；本作只需保证"不写坏别的格子"）。
- 读 + row < -1 ⇒ 返回 0 / 空串。
- 不要当"最后一行"。db.rs 的 row.min(len-1) 夹取如果作用在 -2 上会读到**倒数第二行**——这是错的；**先判哨兵再夹取**。

### 7.3 负列

26 个站点出现负列，取值集合 {-3, -2, -1}，主要在 arg0 = 10（5 处）、13（5 处）、11（3 处）、12（3 处）。例：

- CE267 pc24 250 [24, 1600021, -3, 70111, 1600007]

规则：**夹到 0**。

### 7.4 越界 clamp

crates/wolf-game/src/db.rs:455 的写法（沿用即可）：

```rust
let row = row.min(table.rows.len().checked_sub(1)?);
```

代码注释原文的理由：脚本会用负数行当"最后一行"哨兵，而且有时会给出**恰好越界一格**的行号；夹取比 unanswered 安全，因为 unanswered 会让调用方拿到 0 并继续跑错分支。

但**必须先处理 -1 / < -1 哨兵，再夹取**（见 7.2 的坑）。
