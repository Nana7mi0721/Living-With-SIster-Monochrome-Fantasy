## 6. 解析算法（给 crates/wolf-game 直接用）

### 6.1 主流程伪代码

```rust
struct DbRef {
    cont: Container,   // CDataBase | SysDatabase | DataBase
    ty:   usize,       // 容器内类型下标
    row:  i32,
    col:  usize,
    is_write: bool,
    op:   u8,          // 0..7
    string_write: bool // argc == 4
}

fn resolve(cmd: &Command, vars: &mut Vars) -> Option<DbRef> {
    let flags = cmd.arg(3) as u32;

    // 1 容器 bits 8..9  0=CDataBase 1=SysDatabase 2=DataBase
    let cont = match (flags >> 8) & 3 {
        0 => Container::CDataBase,
        1 => Container::SysDatabase,
        2 => Container::DataBase,
        _ => return None,
    };

    // 2 方向与算法
    let is_write = (flags & 0x1000) == 0;
    let op = (flags >> 4) as u8 & 7;
    let string_write = (flags & 0x2) != 0;

    // 3 类型 标签优先 arg0 兜底
    let tlabel = norm(cmd.str(1));
    let ty = if !tlabel.is_empty() {
        match db.find_type_unique(cont, &tlabel) {
            Some(i) => i,
            None => identity_or_clamp(cont, eval_magic(cmd.arg(0), vars)),
        }
    } else {
        identity_or_clamp(cont, eval_magic(cmd.arg(0), vars))
    };

    // 4 行 必须求值
    let row = clamp_row(eval_magic(cmd.arg(1), vars), db.row_count(cont, ty));

    // 5 列 标签优先 arg2 兜底
    let flabel = norm(cmd.str(3));
    let col = if !flabel.is_empty() {
        match db.find_field_unique(cont, ty, &flabel) {
            Some(i) => i,
            None => clamp_col(eval_magic(cmd.arg(2), vars), db.field_count(cont, ty)),
        }
    } else {
        clamp_col(eval_magic(cmd.arg(2), vars), db.field_count(cont, ty))
    };

    Some(DbRef { cont, ty, row, col, is_write, op, string_write })
}
```

### 6.2 归一化与兜底规则

| 步骤 | 规则 | 理由 |
|---|---|---|
| 标签归一化 | @@BT@@.replace('\u2014','-').replace('\u2015','-').replace('\u3000',' ')@@BT@@ 再 trim、去尾部 NUL | 数据里同时存在 U+2014 / U+2015 破折号与 U+3000 全角空格 |
| 类型名唯一性 | 三容器里唯一重名的类型只有 属性耐性 (DataBase#11 与 CDataBase#3)，已被容器位分开 | 剩余 2 条歧义可忽略 |
| identity 兜底 | @@BT@@ty = arg0 if 0 <= arg0 <= 39@@BT@@（三容器同规则） | arg0 在 0..12 段 identity 率 100% |
| 越界兜底 | 行列越界一律夹到合法范围并计数告警 不 panic | arg2 会超出 .dat 字段数（§5.2） |
| 冲突 | 标签命中但 arg2 指向别处 以标签为准 并计数 | 33 条过期标签样本（§5.4） |

实测解析来源分布（全 2,663 条）：

| 来源 | 条数 | 说明 |
|---|---|---|
| F 字段标签在容器内唯一 | 799 | 最可靠 |
| T 字段标签在已定类型内唯一 | 236 | 也可靠 |
| A 仅靠 arg2 恒等 | 1,227 | 有风险 但多数落在 DataBase 0..12 段 |
| O arg2 越界 | 353 | 夹到合法范围 |
| X 类型无法解析 | 48 | 跳过并告警 |

### 6.3 RuntimeDb 设计建议

```rust
enum Cell { Int(i32), Str(String) }

struct RuntimeDb {
    cdatabase: Vec<Vec<Vec<Cell>>>,
    sysdatabase: Vec<Vec<Vec<Cell>>>,
    database: Vec<Vec<Vec<Cell>>>,
    battle_temp: Vec<Vec<Vec<Cell>>>,
}
```

关键点：

1. DataBase 的配置类类型（#15 用語設定 #16 画像/音声設定 #17 システム設定）只有 1 行，
   但必须当可变单元格存 —— 本作有 8 条指令往 DataBase#26 効果音 列里写（CE270 pc2008..2712）。
2. CDataBase#18 基本システム用変数 的热行（97/98）在 .dat 里是占位文本 真值由脚本写入（§7.2）。
3. 越界列必须按 存在就返回默认值 0 或空串 处理 —— 引擎运行时记录比 .dat 宽（§5.2），
   那些额外列在 .dat 里没有初值 但本作会读它们（例如 arg0=19 列号 48）。
