## 8. M1 标题画面的 108 次 124

### 8.1 为什么会是 108 次

- **标题事件本身（ev42）里没有 124**，它的 210 调用闭包 {42, 549, 14, 132} 里也没有。
- 108 次全部来自 **run_condition = 2/3 的并行公共事件**（每帧都在跑）：主犯是
  `ev224 ウィンドウ処理`（读 12004 / 12005 / 12002 / 1600031 的 field 8 / 0 / 1 / 3）、
  `ev512 / ev41 マウス感知`（0x3000 的 7 / 8 / 9 / 10）、以及 `ev521 アルバム` 系列。
- 所以「108」是**每 200 帧的并行事件流量**，不是「标题画面有 108 个功能点」。
  但因为所有 `111` 判断都读到「没被写入的旧值」，标题按钮的悬停/点击**全部失效**。

### 8.2 最小实现清单（按这个顺序做，做完标题就能点）

1. **`0x4000` field 8**（悬停，588 处）+ **`0x3000` field 7/8/9/10**（鼠标三态 + 滚轮）——
   只这两组就覆盖标题画面几乎全部交互。
2. **`0x4000` field 0/1/2/3**（图片 X/Y/倍率）——按钮命中区和窗口框位置。
3. **`0x4000` field 9**（使用中）——立绘/眨眼收尾，不做会「立绘残留」。
4. **`0x3000` field 20/21**（鼠标坐标）——少数把图直接画在鼠标上的地方。
5. 其余（field 4/10、0x1000、0x1200、0x4400）之后补，缺了不影响标题。

### 8.3 验收标准

- 跑 `wolf-cli run --event 42 --frames 200`，日志里 **0 条**
  `124 SetVariableEx: sub-op … not reverse-engineered`。
- 标题画面按钮（trace 里已有的图片番号 `#12004 #12005 #12053 #12054 #12500 #12501 #12502`）
  能随鼠标移动换图（カーソル変更 走 `150` 重画），点击能进 `125` / `210` 分支。
- 已知图片几何（work/_m1_trace.txt 实测）：`#12500 kind4 855,200`、`#12501 kind2 text 715,115`、
  `#12502 kind1 scale25 855,430`、`#12005 Draw <TRI-RIGHT>`。
