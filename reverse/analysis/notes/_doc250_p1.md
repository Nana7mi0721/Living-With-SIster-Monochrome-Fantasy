### 0.1 给 Rust 实现（crates/wolf-game / crates/wolf-vm）的 5 条硬要求

1. **容器用 @@BT@@(flags >> 8) & 3@@BT@@ 判**，不要用 bit9 或 bit12。bits89 == 2 时 bit9 恰好为 1（所以
   「bit9 = DataBase」碰巧成立），但 SysDatabase 只置 bit8、bit9 == 0，会漏判。
2. **方向用 bit12 (0x1000) 判**：1 = 读（DB 单元格 → arg4 变量），0 = 写（arg4 → DB 单元格）。
   不要用 bit16（那是「有没有类型名标签」的记账位）。
3. **arg1 必须当魔法数字求值**。当前 @@BT@@crates/wolf-vm/src/exec.rs:1578@@BT@@ 只对 arg0 和 arg4 调了
   @@BT@@Magic::decode(...).is_storage()@@BT@@，arg1 / arg2 原样透传 —— 而实测前 16 热单元格里有 4 个的 arg1
   是 @@BT@@1600000+@@BT@@ 的自身变量（如 @@BT@@[19,SV32,0,...]@@BT@@、@@BT@@[21,SV0,0,...]@@BT@@）。
4. **类型 / 列用「标签优先」策略解析**（§6 给伪代码）。用 arg2 当 .dat 字段下标会在 @@BT@@画像/音声設定@@BT@@、
   @@BT@@システム設定@@BT@@、@@BT@@状態設定@@BT@@ 等类型上直接读错字段。
5. **op != 0 的写必须实现成单元格算术语义**（加/减/乘/除/余/最大/最小），不能当普通赋值。本作物品、金钱、
   HP 的钳制习惯用法全靠 op6 / op7（见 §3.4）。
