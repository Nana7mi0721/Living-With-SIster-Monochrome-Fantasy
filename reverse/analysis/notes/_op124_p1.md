# opcode 124 SetVariableEx（ウディタ「変数操作＋」）语义规格

> 目标：把 **opcode 124 `SetVariableEx`** 的语义写到「Rust 程序员照抄就能实现」的程度。
> 这是当前 M1（标题画面）唯一还看得见的功能缺口：标题跑 200 帧触发 **108 次** 124，全部落到
> 「sub-op not reverse-engineered; value kept」，于是所有依赖它的判断恒假。
> 数据来源：**本作二进制实测**（work/_ce_full.json = 550 公共事件 / work/maps_full.json = 9 张 .mps 的全部事件，
> 合计 **1,045 条 124**，其中公共事件 579 + 地图事件 466）+ 官方编辑器文档 YADOT-WOLF
> （work/_yado_0600.txt，页面更新 2026/06/06，cp932 抓取）+ 数据流交叉验证（work/_probe124_*.py）。
> 置信度标记：**★★★ 已确证**（注释 + 功能必然性双重支撑）、**★★ 高**（多条独立样本自洽）、
> **★ 中**（单点样本 + 结构自洽）、**未定**（列候选与判别方法，不要凭直觉实现）。
> **标「未定」的请走 fallback（返回 0 或保持变量不变）并留一行日志。**

## 0. 结论速览

```
sub-op 分解：sub = (type << 12) | modifier
  0x1000 = type 1 (キャラ)                modifier 0
  0x1200 = type 1 (キャラ)                modifier 0x200  マップズーム反映
  0x2000 = type 2 (位置=画面座標系)        本作 0 次，未实测
  0x3000 = type 3 (その他)                modifier 0
  0x4000 = type 4 (ピクチャ)              modifier 0
  0x4400 = type 4 (ピクチャ)              modifier 0x400  エフェクト補正なし
```

| sub | 含义 | argc | 全库 | 公共事件 | 地图事件 | 置信度 |
|---|---|---|---|---|---|---|
| `0x1000` | 取**角色**属性（坐标 / 朝向 / 画面坐标 / 事件ID …） | 4 | 39 | 37 | 2 | ★★★ |
| `0x1200` | 同上，**画面坐标按マップズーム反映** | 4 | 1 | 1 | 0 | ★★ |
| `0x2000` | 取画面像素坐标处信息（px座標のイベントID 等） | 4 | **0** | 0 | 0 | 未实测 |
| `0x3000` | 取**その他**（地图号 / BGM / 鼠标状态 / 鼠标坐标 / 处理中事件号 …） | **3** | 278 | 174 | 104 | ★★★ |
| `0x4000` | 取**图片(ピクチャ)**属性（XY / 倍率 / 图案 / 光标悬停 / 使用中 …） | 4 | 719 | 359 | 360 | ★★★ |
| `0x4400` | 同上，**ピクチャエフェクト补正なし** | 4 | 8 | 8 | 0 | ★★ |
| 合计 | | | **1,045** | 579 | 466 | |

三条必须先记住的硬结论：

1. **永不阻塞、永不返回栈值。** 124 是纯查询：算出一个 `i64`，直接写进 `args[0]` 指定的存储槽，然后
   `pc += 1`。没有 wait、没有 branch、没有 branch_depth 变化（全库 1,045 条 branch_depth 全为 0）。
2. **只有 5 种 sub 值，且只有 0x3000 是 argc=3。** argc=3 的形状是 `[dst, sub, field]`（没有 object 槽）；
   argc=4 是 `[dst, sub, obj, field]`。实现按 `args.len()` 分派即可，别假设固定 4 槽。
3. **不存在复合赋值。** 1,045 条的 `dst` 高 4 位**全为 0**（`dst >> 28 == 0`），即编辑器里的
   「代入演算子」== `=`、「結果を±999999に収める」== 未勾选。所以实现就是纯覆写；
   若将来遇到高 4 位非 0 的样本，说明 124 用了别的编码，需重新反推（见 §9.5）。

## 1. 参数编码

### 1.1 形状

```
argc = param_count - 1          （既有 loader 已处理；见 docs/FORMAT_SPEC.md §3）

argc == 4:  args = [dst, sub, obj, field]
argc == 3:  args = [dst, sub, field]        // 只有 0x3000 会这样出现（278/278）

dst   : 魔法存储字（magic storage word），高 4 位 = 0
        1600000+n = 自変数 n              （本作 124 的绝大多数目标）
        2000000+n = 通常変数 n
        9000000+n = システム変数 n
        1100000+n = マップイベントの自変数（地图事件侧）
        细节见 docs/OPCODE_SPEC.md §2
sub   : = (type << 12) | modifier，低 8 位恒为 0
obj   : 被查询对象编号，**通常是魔法值**（可以是变量引用，如自変数 1600021 / 1600031 / 1600040）
field : 属性下标，小整数（本作 0..10）
```

### 1.2 obj 必须是「求值后」的对象编号 ★★★

`obj` 不是常量字段，而是和普通数值参数一样要过 magic-value 求值器：

- `0x1000` 的 obj 是**角色 ID**，可以是 `-1/-2/…/-7`（负数哨兵），也可以是 `1600000+n`（自変数里存的事件 ID）。
- `0x4000/0x4400` 的 obj 是**ピクチャ番号**。本作图片号会到 **5 位数**（`12004`、`12500`、
  `3149840` 这类），且大量样本用变量间接给出：
  - ev224 pc322 `124 [self13, 0x4000, 1600031, 8]` —— 图片号存在自変数 self31 里；
  - ev521 全员：`124 [self10, 0x4000, 201..233 / 301.. / 401.. / 501.. / 601.. / 701.., 8]`。
- 因此**不要**用 `(uint8_t)int_args[1]` 这类截断（docs/OPCODE_SPEC.md §5.19 里针对 150 的那句
  对本作是错的，图片号到 5 位数，必须用完整 i32）。这里同理，obj 必须走 `eval_num()`。

### 1.3 目标写入语义

`dst` 是普通数值存储槽，行为与 `121 SetVariable` 的赋值完全一致（**不**做 ±999999 钳制）。
`dst` 指向不可写的槽时，按「静默丢弃 + 一条 warn 日志」处理。

## 2. `0x3000` その他（argc=3）

`field` → 语义。**本作只用过 {0,1,7,8,9,10,11,12,17,18,20,21}**，其余 0 次。

| field | 语义 | 值域 / 单位 | 本作次数 | 置信度 | 决定性证据 |
|---|---|---|---|---|---|
| 0 | 現在のマップ番号（SysDB[0:マップ設定] のデータID） | 整数 | 若干 | ★★★ | ev126 pc56/pc60 读→等 1 帧→再读→`111 … !=`，注释「マップが変わっていた場合」；ev270 pc2729「マップが変わった時の処理」 |
| 1 | 再生中のBGM番号（SysDB[1:BGMリスト] のデータID；未設定或按文件名演奏则 -1） | 整数 | 2 | ★★ | ev188 pc9 注释「現在のBGMを保存する」→ pc10 `self25 = その他(1)` |
| 7 | マウス**左**クリック状態 | 0=未按 / 1=按住 / 2=刚按下 | 大量 | ★★★ | ev225 pc51 注释「左クリック決定」→ pc54 读 7 → pc55 `111 == 2` → pc57 `125 [1]`（决定键）；ev41 cself 名 `左クリック感知` |
| 8 | マウス**右**クリック状態 | 同上 | 大量 | ★★★ | ev225 pc62 注释「右クリックキャンセル」→ pc63 读 8 → `111 == 2`；ev41 cself 名 `右クリック感知` |
| 9 | マウス**中**（滚轮按下）クリック状態 | 同上 | 少数 | ★★ | ev41 pc14 + cself 名 `中クリック感知`，命中后 `125 [64]` |
| 10 | マウス**滚轮转动量**（±，向下为负） | 有符号，通常 ±1..±3 | 少数 | ★★ | ev41 pc15 + 注释「下ホイールは-の値なので-1かけて自然数に戻す」（pc32-33）；ev224 pc103 |
| 11 | マウス坐标下的マップイベントID（无则 -1，多个取最小） | 整数 | 少数 | ★★ | ev225 pc70 起「マウス画像変更」成对使用 11/12 |
| 12 | マウス坐标下的**接触範囲拡張**事件ID（无则 -1） | 整数 | 少数 | ★ | ev225 pc71 |
| 17 | **未定**。くうきいぬ 消息窗口包用来算自增计数（`v/5 %100 *15000000`） | 未知 | 4 | 未定 | ev265/266/267/268；只影响消息窗口工具，M1 不需要 |
| 18 | 処理中的自動/接触/決定キー起動イベント番号；**コモンイベントなら +500000**，无则 -1 | 整数 | 少数 | ★★★ | ev224 pc35 `self10 = その他(18)` → pc36 `111 self10 == 500065` → 调公共事件 65；ev270 pc172/pc220 注释「this=呼び出し元イベント」 |
| 20 | マウス**X座標**（画面像素，1024×576 基准，左上=0） | 像素 | 少数 | ★★ | ev224 pc597 读出后与 `0x4000` 读到的图片 X 比较；ev225 pc47/48 把值直接写进 150 的 X/Y 槽 |
| 21 | マウス**Y座標** | 像素 | 少数 | ★★ | 同上 pc284 / pc619 |

**并行事件（run_condition=2/3）里** `field=18` 取的是「正在运行的自动/接触/决定键事件」，官方文档
「並列実行以外のイベントを実行していない場合は -1」。实现时对并行协程返回 -1 或最近一次非并行事件均可，
本作只用它做 500065 判断（消息窗口），影响面小。

其它 field：新版官方列表还有 `タイルセット番号 / マップイベント数 / マップサイズ / ズーム拡大率 /
ズーム中心 / BGS番号 / BGM再生位置 / 曲の長さ / 起動EvID / このマップイベントID / このコモンイベントID /
Ev行数 / 消費メモリ / 言語 / パッドタイプ / マウス画面内 / マウスX座標の変化` 等，但**本作一次都没用过**，
而且**新版与本作的 index 编号并不一致**（新版 BGM=8，本作 BGM=1；新版 処理中Ev番号=17，本作=18）。
