## §8 字符串实参（task-26 补测）

### §8.1 布局：字符串实参夹在数值实参和返回目的之间

21,655 个 `210`/`211`/`300` 站点零反例：

```
a[0]               目标（500000+n / 600000+n / 210 的 0）
a[1]               param_status
a[2 .. 2+nnum]     数值实参        （在调用方上下文求值）
a[2+nnum .. +nstr] 字符串实参      （见 §8.2）
a[2+nnum+nstr]     返回目的操作数  （仅 bit24=1 时存在）
```

即 `len(a) - 2 - number_count == string_count + (1 if 返回位 else 0)`，21,655/21,655 成立。

### §8.2 一个字符串槽的两种形态

| 形态 | 判据 | 取值 |
| --- | --- | --- |
| 字面量 | `string_enabled(k)` = bit12+k 置位 | `stringArgs[1 + k]` |
| 变量引用 | `string_enabled(k)` 清零且该槽字 != 0 | 该字是 magic，在**调用方**上下文求值（`eval_str`） |

* `stringArgs[0]` 分别是 `210` 的空占位（8,171/8,171 站点都是空串）和 `300` 的被调事件标题。
  所以第 k 个字面量在 `stringArgs[1 + k]`，**不是** `stringArgs[k]`；照 k 取会让 300 把标题当参数传下去。
* 两种判据在本作数据上完全等价：16,110/16,185 个槽字是 0 且使能位=1；使能位=0 的 73 个槽字全部非 0
  （`1600009`×24 · `1600005`×23 · `1600007`×14 · `1600008`×8 · `1600006`×3 · `3000000`×3）。
  实现里两个条件都判，这样「字面量恰好是空串」和「变量 0」不会互相污染。

### §8.3 落点：被调事件的 CSelf5..8

`1_600_000 + n` 是「当前公共事件的 CSelf[n]」（magic 解码成扁平槽 `600 + n`），所以：

| 编辑器输入框 | magic | 扁平 self 槽 | 实现常量 |
| --- | --- | --- | --- |
| 数值输入 1..4 | `1_600_000..1_600_003` | 600..603 | `magic::SELF_ARG_BASE + i` |
| 字符串输入 1..4 | `1_600_005..1_600_008` | 605..608 | `SELF_ARG_STRING_BASE + k` |

CSelf4 是编辑器的空档，本作也没有任何站点读 `1_600_004`。

### §8.4 规模（这决定值不值得改）

| 量 | 数 |
| --- | --- |
| 调用点总数（`210`×20,485 · `300`×1,170 · `211`×4） | 21,659 |
| **带字符串实参的站点** | **8,260**（`210`×8,191 · `300`×69 · `211`×0） |
| `string_count` 直方图 | `210` {0:12,294, 1:250, 2:7,941} · `300` {0:1,101, 1:60, 3:9} · `211` 全 0 |
| 被调事件读 `1_600_005` 的站点 | **8,229** |
| 被调事件读 `1_600_006` 的站点 | **7,957** |
| 被调事件读 `1_600_007` / `1_600_008` 的站点 | 10 / 44 |

8,256 个站点解析出了被调事件，4 个 `300` 的标题在本作里不存在（原作死代码）。
最高只用到 3 个字符串实参，**从没出现 CSelf8**，所以上限取 4 是安全的。

按「消费 vs 转发」细分（转发 = 被调方又用 `210/300` 把它传下去，消费 = `112/122/250/101/150/221`）：

| 实参 | 消费 | 转发 | 未用 |
| --- | --- | --- | --- |
| arg#0 → CSelf5 | 442 | 7,787 | 27 |
| arg#1 → CSelf6 | 153 | 7,787 | 10 |
| arg#2 → CSelf7 | 0 | 0 | 9 |

被调方触及这些槽的 opcode：`210`×15,616（转发）· `112` 字符串条件×5,347 · `122` 设字符串×285 ·
`250`×62 · `150`×52 · `221`×2。分槽：CSelf5 {210:7,829, 112:4,882, 122:117, 250:4}、
CSelf6 {210:7,787, 112:457, 122:155, 250:4, 221:1}、CSelf7 {122:13, 250:10, 112:8, 150:3, 221:1}、
CSelf8 {150:49, 250:44}。

结论：绝大多数调用点是**逐层转发的包装器**，真正的消费者埋在末端。丢掉字符串实参不会让任何事件报错，
只会让最末端的 `112` 比较全部失败、`150` 的说明栏全空——正是「消息窗口不显示任何字」的症状。

### §8.5 铁证

1. **字面量路径**：ev109 pc63 `300 [0, 4113, 0, 1600005] s=['X[移]メニュー時文章表示', '外すことができません']`。
   `4113 = 0x1011` ⇒ num=1 / strc=1 / 使能位 0 置位 ⇒ 字面量 `s[1]`。被调 ev101 在 pc35 执行
   `122 [1600005, 2304] s=[BSn, LF]`（把收到的 `\n` 两字符转成真换行）——它读的正是自己的 CSelf5。
2. **文本消费路径**：ev66 `X[共]万能ウィンドウ説明欄変更` pc23 的 `150` 文本参数是
   `\f[\cself[18]]\space[0]<C>\cself[5]`，直接用 cself[5] 当说明栏正文。
3. **转发路径**：包装器 ev264 `○◆メッセージウィンドウ[インタフェ—ス]`（被 7,787 个站点调用）
   pc45 `210 [600101, 17, 1600000, 1600006]`（`17 = 0x11`：num=1 / strc=1 / 使能位清零 ⇒ 转发自己的 CSelf6）、
   pc47 `210 [600104, 18, 0, 0, 1600005]`（转发自己的 CSelf5）、pc48 `210 [600103, 4113, 1600002, 0]`（字面量空串）。
4. **混合路径**：ev119 pc22 `300 [0, 24625, 0, 1600006, 1600005, 1600005] s=[标题, '', '使用対象を', '選択して下さい']`，
   `24625 = 0x6031` ⇒ num=1 / strc=3 / 使能位 (0,1,1) ⇒ arg0 是变量（自己的 CSelf6）、arg1/arg2 是 `s[2]`/`s[3]`。
5. **纯变量路径**：ev6 pc1 `300 [0, 18, 1600000, 1600001, 1600005] s=[标题]`，`18 = 0x12` ⇒ num=2 / strc=1 / 使能位清零，
   唯一的字符串实参是变量 `1600005`，此时 `len(s) = 1` 只有标题。

### §8.6 实现改动（crates/wolf-vm/src/exec.rs）

* `Signal::Call` / `Signal::CallByName` 各加 `strings: Vec<String>`（`Signal` 只在本文件内 match，
  其他 crate 不匹配它）。
* 新常量 `SELF_ARG_STRING_OFFSET = 5`、`SELF_ARG_STRING_BASE = magic::SELF_ARG_BASE + 5`（= 605）、
  `SELF_ARG_STRING_SLOTS = 4`。
* `fn string_arguments(cmd, inst, vars, status) -> Vec<String>`：按 §8.2 逐槽解析，`min(string_count, 4)` 封顶。
  字面量**不做转义展开**——`\cself[..]`、`\.` 之类要留到被调方的 `101`/`150` 才展开，提前展开会二次展开。
* `spawn_child` 在写完数值实参后 `self_vars.set_str(SELF_ARG_STRING_BASE + k, text)`；
  `SelfVars` 本身就是定长 1000 槽（数值 + 字符串各一套），越界忽略，所以不会无限增长。
* `call_arguments` 改成返回 `(Vec<i32>, Vec<String>, Option<i32>)`。

### §8.7 回归测试

| 测试 | 断言 |
| --- | --- |
| `string_arguments_land_in_cself5_and_cself6` | 两个字面量实参分别落在 CSelf5/CSelf6，被调方的两个 `112` 分支都走对 |
| `call_by_name_does_not_pass_its_own_title_as_a_string_argument` | `300` 的字面量从 `s[1]` 取，不会把标题当参数 |

### §8.8 未证实

* 「编辑器 4 个字符串输入 → CSelf5..8」来自外部交叉验证报告，本作数据只用到 CSelf5..7；
  CSelf8 的 44 个读取站点全部在 `150`/`250` 里，且没有任何调用点往 `1_600_008` 送值 ⇒ **CSelf8 在本作是空的**。
* 字符串实参是否会像 `101` 那样立即展开转义，未验证；当前实现不展开（理由见 §8.6）。
* 数值实参上限仍是 `SELF_ARG_BASE + i`（CSelf0..3），超过 4 个的站点本作不存在，未加封顶。

## §9 121/124 二元运算符表纠错（task-26 顺带）

WolfTL `WolfRPG/Command.hpp:51-60` 的注释表把两个运算符写反了：它写 `0x3000 = %`、`0x4000 = ~`。
但 WolfTL **没有任何解码运算符的代码**（grep `0x3000` / `modulo` / `divide` 全无命中），所以那张表从来没人验证过。
数据给出的是：

| kind（arg[3] 高位） | WolfTL 注释 | **实测** | 本作站点 | 铁证 |
| --- | --- | --- | --- | --- |
| `0x0000` | `+` | `+` | 多数 | — |
| `0x1000` | `-` | `-` | 214 | ev48 pc46 `Sys8 = self25 op 8`，若为除法得 3（不合理），减法得 20（等于 Sys8 应为 20） |
| `0x2000` | `*` | `*` | 469 | ev63 全篇 `16*rateX` 几何 |
| `0x3000` | `%` | **`/`** | **438** | ev48 pc30 `Sys116/32` = 1024/32 = **32**（= rateX）；若取模得 0，窗口尺寸全 0 |
| `0x4000` | `~` | **`%`** | **107** | ev48 pc172 `self20 %= 10000` 后 `+= 20000` 重编码道具号；ev94 pc291 `self67 = self60 % 3600` 再 `/60` 秒转分 |
| `0x6000` | 未定义 | `rand(min, max)` | 1,101 | 已在 §3.2 确认，本次不动 |
| `0x5000` / `0x7000` / `0x8000` / `0x9000` | `&` / `\|` / `^` / `<<` | 沿用 | 本作 0 站 | 无法用数据校准 |

补充反证：ev48 的三条旧処理分支里 `Sys23 = Sys8 / 2` 恒成立（12/2=6、24/2=12、30/2=15），
取模会得到 0/0/0，ルビ字号直接消失。

实现（`crates/wolf-vm/src/exec.rs` `fn binary_op`）：`0x3` → `wrapping_div`，`0x4` → `wrapping_rem`，
除零/模零都保留左操作数（与原实现一致）。测试：`binary_operator_table_matches_the_editor`、
`set_variable_divides_where_the_old_table_took_a_remainder`。
