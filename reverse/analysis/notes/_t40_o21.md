### 2.1 arg1 / arg2 的负值：两套独立机制，不是「夹到 0」【★已实测纠正】

⚠️ 早先版本这里只写了「-1 / -2 / -3 = 当前行 / 循环当前项 / 最后一项」，并建议
「负行号夹到 0；负列号夹到 0 或 字段数-1」—— **错的**。逐站点复测（550 个公共事件共
2,592 条 `250`，其中负行 47 条、负列 26 条；`work/_pd_84_row2value.py` /
`work/_pd_89_negcol.py`，站点明细见 `docs/BATTLE.md` §2.5）：

| 轴 | 值 | 条数 | 方向 | 语义 |
|---|---|---|---|---|
| arg1 | `-1` | 29 | **全部读**（bit12=1） | **查该类型的行数**（row count 元查询），arg2 don't-care。CE48 pc153 `[0,-1,33,0x11000,SV10]` → SV10=17（主人公ステータス），下一条 `179 [SV10]` 就是循环上界 |
| arg1 | `-2` | 17 | **全部写**（flags 恰 0x10000） | **把该类型行数设为 arg4**（set row count），0 = 整表清空。CE191 pc30 `[22,-2,0,65536,2]` 然后手写 row 0/1；CE157 pc28 `[14,-2,6,65536,0]` 注释『全部消去』 |
| arg1 | `-3` | 1 | 读 | **未验证**：疑似"取该行名字 / 文本列"。CE270 pc34 `[21,-3,-3,0x11200,SV90]`，SV90 随后被当作类型号用 |
| arg2 | `-1` | 4 | 读 | **首个空槽 / 首个可用索引**。CE58 pc10 `[1,1600000,-1,69632,SV11]`，前一条注释『最初に見つかった空欄箇所を記憶する変数』 |
| arg2 | `-2` | 19 | **全部写** | **清空该行全部字段**。CE75 pc169 `[5,1600000,-2,65536,0]` 注释『強制全回復』；战斗拷贝一律 `[10..14, row, -2, 65536, SV5]` |
| arg2 | `-3` | 3 | 读 | **未验证**：疑似"取该行名字"，与行数 + 循环配合做按名查找（CE265 命中后记住行号；CE267 同形状） |

实现要点（写进 `Game::database()` 的 250 处理器，而不是 `Databases` 的行列寻址层）：

~~~
match (is_write, row) {
    (false, -1) => return Some(row_count(cont, ty) as i32),          // arg2 忽略
    (true,  -2) => { set_row_count(cont, ty, value); return None }  // value = arg4
    (_, r) if r < -2 => return None /* 未验证：0 + 诊断 */,
    _ => {}
}
if !is_write && col == -1 { /* 未实现：首个空槽 */ }
if is_write  && col == -2 { /* 清空该行所有字段 */ }
if col < -3 { /* 未验证 */ }
~~~

⚠️ **负值不能夹到 0**：`row=-2` 夹成 0 会把整表写到 row 0；`row=-1` 夹成 0 会把行数查询
变成"读第 0 行"。两者都不报错，只会静默产出错数据。
