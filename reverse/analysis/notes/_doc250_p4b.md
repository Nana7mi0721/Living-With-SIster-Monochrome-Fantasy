## 5. arg1 / arg2：行与列

### 5.1 行 / 列 角色判定【已验证】

| 依据 | 结论 |
|---|---|
| arg2 全量取值 0..74（magic 除外，且几乎总是小整数），arg1 经常是 1600000+ 的 magic | **arg2 = 列（项目号），arg1 = 行（记录号）** |
| 字面量 arg1 只有 CDataBase / 运行时空间才 > 0 | 行语义成立（见 §5.3） |
| 列号出现超过该类型 .dat 字段数的值 | 列 ≠ .dat 字段下标（见 §5.2） |

### 5.2 运行时记录比 .dat 行更宽 —— arg2 ≠ 字段下标的最强证据【已验证】

三个最刺眼的例子：

1. **arg0=16（bits89=0）最大列号 47，而它标签指向的 CDataBase#14 ×┣コマンド処理リスト只有 4 个字段。**
2. **arg0=19（bits89=2）最大列号 48，而它标签指向的 DataBase#17 システム設定 / #26 メッセージウィンドウ種類都是 35 个字段**；
   全库只有 #11 属性耐性 / #12 状態耐性（各 100 字段）够 48，但它们不可能是这两个标签。
3. **arg0=8（bits89=2）最大列号 64，而 DataBase#8 状態設定只有 16 个字段。**

⇒ 引擎为每个类型维护的**运行时记录结构包含 .dat 之外的额外列**（编辑器内部字段 / 派生值 / 临时缓存）。
**任何「arg2 就是 .dat 字段下标」的算术映射都会读错字段。**

### 5.3 行号分布：只有运行时空间用到 0 以外的行【已验证】

| arg0 | bits89 | 字面量 arg1 取值集合 |
|---|---|---|
| 18 | 0 | 0..18 及 21 |
| 20 | 0 | 4, 9, 12, 17, 18, 21, 35, 36, 37, 38, 61, 69, 70, 71, 72, 73, 74 |
| 21 | 0 | 4, 6, 17, 21, 37, 38, 69, 70, 71, 72, 73, 75, 78..85 |
| 22 | 0 | 0, 1 |
| 25 | 2 | 0, 1 |
| 0 | 0 | 12 |
| 其余全部 (arg0,bits89) | — | **只有字面量 0** |

结合 §5.1 的「arg1 大量使用 magic」：**DataBase 侧的行号几乎总是通过变量或哨兵给出**（典型写法是
「当前循环索引」「当前角色」这类变量），**实现时严禁把 arg1 当常量用**。
