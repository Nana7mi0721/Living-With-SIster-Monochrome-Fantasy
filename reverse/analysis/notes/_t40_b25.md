**当前实现的实际行为**：`crates/wolf-game/src/db.rs` 的 `cell_address`（≈:420）用
`usize::try_from(row).ok()?` 把负数直接变成 `None`；`num()` / `text()` 也先判
`row<0 || column<0 → None`。`set_num` / `set_text` 只写 `cells` / `texts` 的
`HashMap`，**不做边界校验、不扩容**。⇒ **47 + 26 个站点的数据全部静默丢弃**。

语义应在 `Game::database()`（不是 `Databases` 的行列寻址层）这样实现：

~~~text
读：row == -1             -> return Num(row_count(cont, ty))    // arg2 忽略
读：col == -1             -> 未实现，按"首个空槽"语义（返回 0 + 诊断）
读：row <= -3 / col <= -3 -> 未实现（返回 0 + 诊断）
写：row == -2             -> set_row_count(cont, ty, arg4)      // arg4 = 新行数，0 = 清空
写：col == -2             -> 清空该行所有字段
其余                      -> row >= 0 正常索引；写越界要扩容而不是丢弃
~~~

⚠️ **不要"负值一律夹到 0"**：`row=-2` 夹到 0 会**把整表写到 row 0 上**；`row=-1` 夹成 0 会把
行数查询变成"读第 0 行"。两者都不报错，只会静默产出错数据 —— 这正是当初
`CData (0,100,0) unanswered` 一路查不出来的同一类问题（见 §2.6）。
