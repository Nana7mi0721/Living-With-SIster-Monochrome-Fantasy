fix(hud): harden sprite-sheet cell clamp for the CE506 eye strip

Common event 506 blinks the DLC eye overlay (picture -6, a 3x1 sheet of
open/half/closed eyes) with pattern 1->2->3->2->1. Retail aborts there with
"Pattern number is too large! > ID-6 Pattern 3(Max2)" whenever the sheet has
fewer frames than the command asks for - which is exactly what the user hit at
day 100 on the pre-v6 two-frame dlc_imouto01_eye.png. The re-installed v6 patch
ships a 1536x576 three-frame sheet, so the shipped data is consistent again.

This port has no such abort path: picture_frame falls back to the first cell for
any index past columns*rows, so a stale/corrupt sheet degrades gracefully and is
never read out of bounds. Document that intent and lock it with a regression test
that also pins the whole-screen-layer placement of picture -6.
